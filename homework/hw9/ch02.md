# 第 2 章　第一次呼叫 API

## 【本章重點】

呼叫 LLM API，其實就是**用程式送出一張寫好格式的「點餐單」（HTTP 請求），再收回一張「出餐單」（JSON 回應）**。
我們先用 `requests` 手動送出請求，親眼看懂原始 JSON 裡每一層的意思；再換成 Google 官方的 `google-genai` SDK，體會它幫我們省掉了哪些麻煩。
最後把這些包成一個函式 `call_llm(messages)`，這是全書所有程式的起點。

---

## 【為什麼需要這一章】

第 1 章我們在自己的電腦上用 `random` 模擬了「文字接龍」。但那只是一張手寫的小表格，真正的 LLM 有數十億個參數，**不可能放在你的 Colab 裡跑**。

真正的模型放在 Google 的伺服器上。所以我們要解決的問題是：

> **我的 Python 程式，要怎麼把問題送到 Google 的伺服器，再把答案拿回來？**

答案就是 API。這一章是全書第一次「真的」跟 LLM 說話。

## 【觀念解說】

### 2.1 API 與 HTTP 請求：點餐單與出餐單

**API（Application Programming Interface，應用程式介面）**：一個系統對外開放的「窗口」，規定好別的程式要用什麼格式來找它、它會用什麼格式回覆。

**比喻：去餐廳點餐。**

你不會走進廚房自己煮，而是填一張**點餐單**交給櫃台；廚房做好後，櫃台給你一份**餐點和收據**。點餐單有固定格式：哪一桌、點什麼、要不要辣。格式寫錯，櫃台就會退回來。

| 餐廳 | API |
|------|-----|
| 櫃台的地址 | **URL**（網址，例如 `https://generativelanguage.googleapis.com/...`） |
| 「我要點餐」這個動作 | **HTTP 方法**（method），送資料通常用 `POST` |
| 出示會員卡 | **標頭**（header）裡的 API key |
| 點餐單的內容 | **請求主體**（request body），用 JSON 格式寫 |
| 餐點和收據 | **回應**（response），也是 JSON 格式 |
| 「好的，馬上來」／「你沒帶會員卡」 | **狀態碼**（status code），例如 200、400 |

**HTTP（HyperText Transfer Protocol，超文字傳輸協定）**：網路上程式互相傳資料的共同規則。你用瀏覽器開網頁，背後也是 HTTP。

**JSON（JavaScript Object Notation）**：一種用文字表示資料的格式。它長得跟 Python 的 dict 和 list 幾乎一模一樣，所以 Python 很容易讀寫它。

```text
  ┌──────────────┐        HTTP 請求（POST）         ┌──────────────────┐
  │              │ ───────────────────────────────▶ │                  │
  │  你的 Python  │  URL：要找哪個模型                │  Google 的伺服器  │
  │    程式      │  標頭：API key（我是誰）            │   （Gemini）     │
  │  （Colab）   │  主體：JSON（我的問題、參數）        │                  │
  │              │ ◀─────────────────────────────── │                  │
  └──────────────┘        HTTP 回應                  └──────────────────┘
                     狀態碼：200（成功）
                     主體：JSON（模型的回答、用了多少 token）
```

**常見的狀態碼：**

| 狀態碼 | 意思 | 在 Gemini API 常見的原因 |
|-------|------|----------------------|
| `200` | 成功 | 一切正常 |
| `400` | 請求格式錯誤 | JSON 寫錯、參數名稱拼錯；**金鑰無效**時 Gemini 也常回 400（訊息含 `API_KEY_INVALID`） |
| `401` / `403` | 沒有權限 | 沒帶金鑰、金鑰沒有權限（其他家的 API 金鑰錯誤時常回 401） |
| `404` | 找不到 | **模型名稱打錯**，或模型已經停用 |
| `429` | 請求太多 | 超過免費額度的速率限制，等一下再試 |
| `500` / `503` | 伺服器錯誤 | Google 那邊忙不過來，稍後再試 |

### 2.2 本書使用的端點與模型

**端點（endpoint）**：API 裡某個具體功能的網址。本書使用 Gemini 的 `generateContent`（產生內容）端點：

```text
POST https://generativelanguage.googleapis.com/v1beta/models/{模型名稱}:generateContent
```

**模型名稱**：本書使用 `gemini-3.5-flash-lite`。選它的原因：

- 有**免費額度**，學生不用綁信用卡。
- 回應快，適合練習。
- 預設幾乎不做「思考」（下面 2.6 節說明），回答的 token 數比較好預測。
- 還能調整 `temperature`。注意：Gemini 3.6 以後和 Gemini 4 系列的模型會**忽略** `temperature`。

> ⚠️ **關於版本**
> - 本書寫作時（2026 年 11 月），Google 官方文件主推一套新的 **Interactions API**，`generateContent` 被標示為「舊版（legacy）」，但官方說明它**仍然完整支援**。
> - 本書選用 `generateContent`，是因為它的 `contents`（對話內容）和 `role`（角色）結構，跟 OpenAI、Anthropic 等其他家的 API 觀念幾乎一樣。學會這一套，換別家也看得懂。第 11 章會再介紹新的 Interactions API。
> - 如果執行時出現 `404` 或「模型不存在」，代表模型名稱可能改了。請到官方文件 <https://ai.google.dev/gemini-api/docs/models> 查目前的模型名稱，改掉 `MODEL_NAME` 那一行即可。

### 2.3 請求長什麼樣子

一個最簡單的請求主體（body）長這樣：

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "用一句話解釋什麼是 API" }
      ]
    }
  ]
}
```

一層一層拆開看：

```text
  contents          ← 「對話內容」：一個 list，裡面每一個元素是一則訊息
   └─ [0]           ← 第 1 則訊息
       ├─ role      ← 這則訊息是誰說的："user"（使用者）
       └─ parts     ← 訊息的內容：一個 list，因為一則訊息可以有好幾段（文字、圖片⋯）
           └─ [0]
               └─ text ← 真正的文字內容
```

為什麼 `contents` 是 list？因為一次可以送**整段對話**（第 3 章會用到）。
為什麼 `parts` 也是 list？因為 Gemini 是**多模態（multimodal）**模型，也就是能同時處理文字、圖片、聲音等多種資料，一則訊息可以「一段文字＋一張圖片」。本書只用文字，所以 `parts` 裡永遠只有一個 `text`。

### 2.4 messages 與 role：三種角色

和 LLM 對話時，每則訊息都要標明「是誰說的」，這叫做 **role（角色）**。各家 API 幾乎都有這三種角色：

| 通用角色 | 代表誰 | 用途 | Gemini 的寫法 |
|---------|-------|------|-------------|
| `system` | 開發者（你） | 設定模型的身分、規則、語氣，使用者通常看不到 | 不放在 `contents`，而是放在獨立的 `system_instruction` 欄位 |
| `user` | 使用者 | 使用者說的話 | `"role": "user"` |
| `assistant` | 模型 | 模型之前的回答 | `"role": "model"`（Gemini 叫 model，不叫 assistant） |

**比喻：一場話劇。**

- `system` 是**導演寫給演員的角色說明**：「你演一個親切的校園助理，說話簡短。」觀眾看不到，但演員會照著演。
- `user` 是**觀眾的提問**。
- `assistant` 是**演員之前講過的台詞**。

```text
  通用格式（本書的 messages）                    Gemini 的格式
  ─────────────────────────                    ─────────────────────────
  {"role": "system",    "content": "..."}  ──▶  system_instruction: {"parts":[{"text":"..."}]}
  {"role": "user",      "content": "..."}  ──▶  contents: [{"role":"user",  "parts":[{"text":"..."}]},
  {"role": "assistant", "content": "..."}  ──▶            {"role":"model", "parts":[{"text":"..."}]}]
```

本書的程式**對外一律用左邊的通用格式**（`role` ＋ `content`），由本章最後（程式 2-6）寫的 `call_llm()` 負責轉成右邊 Gemini 的格式。這樣做的好處：以後換成別家 API，只要改 `call_llm()` 裡面就好，其他程式都不用動。

這一章只用到 `system` 和 `user`。`assistant` 要等到第 3 章「記住對話」才會派上用場。

### 2.5 兩個常用參數：temperature 與 max_output_tokens

請求裡可以加一個 `generationConfig`（生成設定）欄位，調整模型怎麼產生回答：

| 參數 | 通用名稱 | 意思 | 常見範圍 |
|------|---------|------|---------|
| `temperature` | temperature | 第 1 章的「抽籤筒」隨機程度。越低越穩定，越高越多變 | 0～2 |
| `maxOutputTokens` | max_tokens | 回答**最多**能用幾個 token，超過就硬切斷 | 依模型，常見數千到數萬 |

- 需要**穩定、正確**的時候（例如等一下要讓程式讀 JSON）：`temperature` 設低，例如 `0`。
- 需要**創意、多樣**的時候（例如幫社團想活動名稱）：`temperature` 設高，例如 `1.5`。
- `maxOutputTokens` 是用來**控制費用和長度**的保險。設太小，回答會被切在一半。

> 其他家 API 把 `maxOutputTokens` 叫做 `max_tokens`，意思一樣。

### 2.6 什麼是「思考」（thinking）

新一代的模型在回答前，可以先在內部產生一段「草稿推理」，再寫出正式回答。這叫做**思考（thinking）**，產生的 token 叫做**思考 token（thinking tokens）**。

- 思考 token **也要算錢**，而且**也算在 `maxOutputTokens` 裡面**。
- 如果模型思考太久、把 `maxOutputTokens` 用光了，正式回答可能是**空的**。

本書用的 `gemini-3.5-flash-lite` **預設只做極少量的思考**（官方稱為 `minimal`），所以不太會遇到這個問題。但如果你換成別的模型，發現回答莫名其妙是空的，請先想到「是不是思考把 token 用光了」，並把 `maxOutputTokens` 調大。

### 2.7 SDK 是什麼

**SDK（Software Development Kit，軟體開發套件）**：官方寫好的工具包，把「組 JSON、送 HTTP、解析回應、處理錯誤」這些繁瑣的事包成簡單的函式。

比喻：`requests` 手寫請求像是**自己填紙本點餐單**，每一格都要寫對；SDK 像是**點餐 App**，你只要點選想吃的，App 自動幫你填好單子送出。

但 App 背後送出的，**還是同一張點餐單**。所以本章先手寫一次，你才會知道 SDK 在背後幫你做了什麼。

### 程式 2-1：用 requests 送出第一個請求

```python
import json
import requests
from google.colab import userdata

# 從 Colab 密鑰讀取 API key（絕對不要寫死在程式裡）
api_key = userdata.get("GEMINI_API_KEY")

# 全書使用的模型名稱，集中放在這裡，要換模型只改這一行
MODEL_NAME = "gemini-3.5-flash-lite"

# 端點網址：模型名稱放在網址裡
url = f"https://generativelanguage.googleapis.com/v1beta/models/{MODEL_NAME}:generateContent"

# 標頭：API key 放在 x-goog-api-key 裡，並告訴伺服器我們送的是 JSON
headers = {
    "x-goog-api-key": api_key,
    "Content-Type": "application/json",
}

# 請求主體：一則使用者訊息
body = {
    "contents": [
        {"role": "user", "parts": [{"text": "用一句話解釋什麼是 API"}]}
    ]
}

# 送出 POST 請求
response = requests.post(url, headers=headers, json=body)

# 印出狀態碼和完整的回應 JSON
print("狀態碼：", response.status_code)
print(json.dumps(response.json(), indent=2, ensure_ascii=False))
```

**逐段解說：**

- **讀取金鑰**：和第 0 章一樣用 `userdata.get()`。
- **`MODEL_NAME`**：全大寫的變數名稱，是 Python 的習慣寫法，代表「這是一個設定值，程式執行中不會改」。全書都用這個變數。
- **`url`**：用 f-string 把模型名稱放進網址。注意網址最後是 `:generateContent`，冒號後面是「要做的動作」。
- **`headers`**：
  - `x-goog-api-key`：API key 放在這裡。**不要把金鑰放在網址裡**（例如 `?key=...`），因為網址很容易被記錄在各種紀錄檔中。
  - `Content-Type: application/json`：告訴伺服器「我送的內容是 JSON」。
- **`body`**：就是 2.3 節拆解過的結構。
- **`requests.post(url, headers=headers, json=body)`**：送出 POST 請求。用 `json=` 參數，`requests` 會自動把 Python dict 轉成 JSON 文字。
- **`response.json()`**：把伺服器回傳的 JSON 文字轉回 Python dict。
- **`json.dumps(..., indent=2, ensure_ascii=False)`**：把 dict 轉成「有縮排、好閱讀」的文字再印出。`ensure_ascii=False` 讓中文正常顯示，不會變成 `金` 這種編碼。

**預期輸出（回答內容、數字和 `responseId` 每次都不同）：**

```text
狀態碼： 200
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "text": "API 是一套讓不同程式彼此溝通的規則和介面，就像餐廳的菜單讓你不用進廚房也能點餐。"
          }
        ],
        "role": "model"
      },
      "finishReason": "STOP",
      "index": 0
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 9,
    "candidatesTokenCount": 31,
    "totalTokenCount": 40,
    "promptTokensDetails": [
      {
        "modality": "TEXT",
        "tokenCount": 9
      }
    ]
  },
  "modelVersion": "gemini-3.5-flash-lite",
  "responseId": "xxxxxxxxxxxxxxxxxxxxxx"
}
```

恭喜，你第一次和 LLM 說到話了！如果狀態碼不是 200，請看本章【常見錯誤】或附錄 B。

### 程式 2-2：拆解回應的 JSON

回應有好幾層，答案藏在很深的地方。先畫出來：

```text
  回應 JSON
   ├─ candidates              ← 候選回答（list）。通常只有 1 個
   │   └─ [0]
   │       ├─ content
   │       │   ├─ role: "model"   ← 這是模型說的話
   │       │   └─ parts
   │       │       └─ [0]
   │       │           └─ text   ← ★ 真正的回答在這裡
   │       └─ finishReason       ← 為什麼停下來：STOP（正常結束）、MAX_TOKENS（被長度上限切斷）
   ├─ usageMetadata           ← ★ token 用量（跟錢有關）
   │   ├─ promptTokenCount       ← 輸入用了幾個 token
   │   ├─ candidatesTokenCount   ← 輸出用了幾個 token
   │   ├─ thoughtsTokenCount     ← 思考用了幾個 token（有思考時才會出現）
   │   └─ totalTokenCount        ← 總共
   ├─ modelVersion            ← 實際回答的模型版本
   └─ responseId              ← 這次回應的編號，查問題時可以用
```

接著用程式把重要的部分挑出來（請接在程式 2-1 後面執行）：

```python
# 把回應轉成 Python dict
data = response.json()

# 一層一層往下取出回答文字
answer = data["candidates"][0]["content"]["parts"][0]["text"]

# 取出停止原因與 token 用量
finish_reason = data["candidates"][0]["finishReason"]
usage = data["usageMetadata"]

print("回答：", answer)
print("停止原因：", finish_reason)
print("輸入 token：", usage["promptTokenCount"])
print("輸出 token：", usage.get("candidatesTokenCount", 0))
print("思考 token：", usage.get("thoughtsTokenCount", 0))
print("總共 token：", usage["totalTokenCount"])
```

**逐段解說：**

- `data["candidates"][0]["content"]["parts"][0]["text"]`：照著上面的樹狀圖，一層一層往下拿。遇到 list 用 `[0]` 取第一個，遇到 dict 用 `["名稱"]` 取值。
- `finishReason`：如果是 `STOP` 代表模型自己覺得講完了；如果是 `MAX_TOKENS` 代表被 `maxOutputTokens` 切斷了。
- `usage.get("thoughtsTokenCount", 0)`：用 `.get()` 而不是 `[]`，因為沒有思考時，回應裡**根本不會有這個欄位**。`.get(名稱, 預設值)` 在找不到時會回傳預設值，不會出錯。`candidatesTokenCount` 也用 `.get()`，因為回答是空的時候也可能沒有這個欄位。

**預期輸出：**

```text
回答： API 是一套讓不同程式彼此溝通的規則和介面，就像餐廳的菜單讓你不用進廚房也能點餐。
停止原因： STOP
輸入 token： 9
輸出 token： 31
思考 token： 0
總共 token： 40
```

> **為什麼要在意 token？** API 是依 token 數收費的。之後做聊天機器人、Agent，每次呼叫的 token 數會越來越多，第 3 章和第 8 章都會回來看這些數字。

### 程式 2-3：加上 system 角色與生成參數

這次我們加上 `system_instruction`（system 角色）和 `generationConfig`（生成參數）。為了不要每次都重寫一堆程式，先把「送請求、拿回答」包成一個小函式。

```python
def gemini_rest(body):
    """用 requests 把 body 送到 Gemini，回傳 (回答文字, 停止原因)"""
    resp = requests.post(url, headers=headers, json=body)
    resp.raise_for_status()  # 狀態碼不是 2xx 就直接報錯，方便除錯
    data = resp.json()
    candidate = data["candidates"][0]
    # 回答被切斷或是空的時候，可能沒有 parts，所以先檢查
    parts = candidate.get("content", {}).get("parts", [])
    text = parts[0]["text"] if parts else ""
    return text, candidate["finishReason"]


body = {
    # system 角色：設定模型的身分與規則（Gemini 把它放在獨立欄位）
    "system_instruction": {
        "parts": [{"text": "你是金門大學的校園小助理，回答一律使用繁體中文，而且不超過兩句話。"}]
    },
    # user 角色：使用者的問題
    "contents": [
        {"role": "user", "parts": [{"text": "期末考快到了，給我一個讀書建議。"}]}
    ],
    # 生成參數
    "generationConfig": {
        "temperature": 0.7,
        "maxOutputTokens": 200,
    },
}

text, reason = gemini_rest(body)
print("回答：", text)
print("停止原因：", reason)
```

**逐段解說：**

- **`gemini_rest(body)`**：把程式 2-1、2-2 的「送出 → 解析」包起來。
  - `resp.raise_for_status()`：如果狀態碼是 4xx 或 5xx，直接丟出例外並顯示錯誤，不會繼續往下跑然後在奇怪的地方出錯。
  - `candidate.get("content", {}).get("parts", [])`：連續用 `.get()`，就算中間某一層不存在，也只會拿到空的 list，不會出錯。
- **`system_instruction`**：注意它**不在** `contents` 裡面，而是跟 `contents` 同一層的獨立欄位。這就是 Gemini 處理 `system` 角色的方式。
- **`generationConfig`**：放 `temperature` 和 `maxOutputTokens`。注意 REST API 的欄位名稱是**駝峰式**（camelCase，例如 `maxOutputTokens`），等一下的 Python SDK 會改成**蛇形**（snake_case，例如 `max_output_tokens`）。

**預期輸出：**

```text
回答： 建議你把範圍切成小單元，每讀 25 分鐘休息 5 分鐘，並在讀完後用考古題檢查自己。考前一晚記得睡飽，效果比熬夜好得多！
停止原因： STOP
```

可以看到 system 的規則生效了：繁體中文、兩句話以內。

### 程式 2-4：親眼看 temperature 和 maxOutputTokens 的效果

```python
question = "幫金門大學的程式社團取一個社團名稱，只要回答名稱就好。"

for temp in [0.0, 1.8]:
    print(f"===== temperature = {temp} =====")
    for i in range(3):
        body = {
            "contents": [{"role": "user", "parts": [{"text": question}]}],
            "generationConfig": {"temperature": temp, "maxOutputTokens": 50},
        }
        text, reason = gemini_rest(body)
        print(f"第 {i + 1} 次：{text.strip()}")

# maxOutputTokens 設得很小，看看會發生什麼事
print("===== maxOutputTokens = 10 =====")
body = {
    "contents": [{"role": "user", "parts": [{"text": "介紹一下金門的特色。"}]}],
    "generationConfig": {"maxOutputTokens": 10},
}
text, reason = gemini_rest(body)
print("回答：", text)
print("停止原因：", reason)
```

**逐段解說：**

- **外層迴圈**跑兩種 temperature：`0.0`（最穩定）和 `1.8`（很隨機）。
- **內層迴圈**每種問 3 次，觀察答案會不會變。這就是第 1 章程式 1-1「抽籤筒」的真實版本。
- `text.strip()`：把回答前後多餘的空白、換行去掉，印出來比較整齊。
- **最後一段**故意把 `maxOutputTokens` 設成 10，讓回答被硬切斷。

**預期輸出（實際名稱每次都不同）：**

```text
===== temperature = 0.0 =====
第 1 次：浯島程式研究社
第 2 次：浯島程式研究社
第 3 次：浯島程式研究社
===== temperature = 1.8 =====
第 1 次：碼上金門
第 2 次：風獅爺程式工坊
第 3 次：Bug 退散研究所
===== maxOutputTokens = 10 =====
回答： 金門擁有豐富的戰地文化
停止原因： MAX_TOKENS
```

**觀察重點：**

- `temperature = 0` 時，三次答案幾乎一樣；`1.8` 時，每次都不同。
- `maxOutputTokens = 10` 時，回答講到一半就斷了，而且 `finishReason` 變成 `MAX_TOKENS`。**以後看到回答莫名其妙斷掉，第一件事就是檢查停止原因。**

> `temperature = 0` 只是「幾乎」固定，不保證 100% 每次一模一樣，因為伺服器端的計算還是可能有細微差異。
> 另外，如果你把 `MODEL_NAME` 換成 Gemini 3.6 以後或 Gemini 4 系列的模型，會發現 temperature 好像沒作用 —— 因為這些模型會**直接忽略**這個參數。

### 程式 2-5：改用官方 SDK

同樣的事情，用 `google-genai` SDK 來做：

```python
from google import genai
from google.genai import types

# 建立連線物件，把 API key 交給它（之後所有呼叫都透過 client）
client = genai.Client(api_key=api_key)

response = client.models.generate_content(
    model=MODEL_NAME,
    contents="期末考快到了，給我一個讀書建議。",
    config=types.GenerateContentConfig(
        system_instruction="你是金門大學的校園小助理，回答一律使用繁體中文，而且不超過兩句話。",
        temperature=0.7,
        max_output_tokens=200,
    ),
)

# SDK 已經幫我們把回答文字和 token 用量整理好了
print("回答：", response.text)
print("停止原因：", response.candidates[0].finish_reason)
print("輸入 token：", response.usage_metadata.prompt_token_count)
print("輸出 token：", response.usage_metadata.candidates_token_count)
print("總共 token：", response.usage_metadata.total_token_count)
```

**逐段解說：**

- `from google import genai`：載入新版 SDK。**注意不是** `import google.generativeai`（那是舊版套件，第 0 章提醒過）。
- `from google.genai import types`：`types` 裡放了各種設定用的類別，例如 `GenerateContentConfig`。
- `genai.Client(api_key=api_key)`：建立一個 **client（客戶端）** 物件。它記住你的金鑰和連線設定，之後所有呼叫都透過它。變數名稱 `client` 全書共用。
- `client.models.generate_content(...)`：對應到 REST 的 `generateContent` 端點。
  - `contents="..."`：可以**直接給一個字串**，SDK 會自動幫你包成 `[{"role": "user", "parts": [{"text": "..."}]}]`。
  - `config=types.GenerateContentConfig(...)`：所有設定集中在這裡，`system_instruction` 也是放在這。
- `response.text`：SDK 提供的**捷徑**，直接幫你從 `candidates[0].content.parts[0].text` 取出文字。
- `response.usage_metadata.prompt_token_count`：token 用量。名稱從 REST 的駝峰式（`promptTokenCount`）變成蛇形（`prompt_token_count`），而且用「`.`」取屬性，不是用 `["..."]` 取 key。

**預期輸出：**

```text
回答： 建議你先整理每科的重點清單，再用番茄鐘法分段複習。考前一晚早點睡，記憶會更牢固！
停止原因： FinishReason.STOP
輸入 token： 34
輸出 token： 38
總共 token： 72
```

> `finish_reason` 印出來是 `FinishReason.STOP`，這是 SDK 用來表示固定選項的寫法（叫做**列舉，enum**），意思跟 REST 的 `"STOP"` 一樣。

**手寫 requests 和 SDK 對照：**

| 要做的事 | requests 手寫版 | SDK 版 |
|---------|----------------|-------|
| 帶金鑰 | 自己寫 `headers` | `genai.Client(api_key=...)` 一次設定 |
| 組網址 | 自己用 f-string 拼 | 只給 `model=MODEL_NAME` |
| 組 JSON | 自己寫好幾層 dict | 直接給字串，SDK 自動包裝 |
| 參數名稱 | 駝峰式 `maxOutputTokens` | 蛇形 `max_output_tokens` |
| 取回答 | `data["candidates"][0]["content"]["parts"][0]["text"]` | `response.text` |
| 處理錯誤 | 自己 `raise_for_status()` | SDK 自動丟出例外 |

**SDK 沒有魔法**：它背後送出的，就是你在程式 2-1 手寫的那張「點餐單」。

### 程式 2-6：包成全書共用的 `call_llm()`

最後，我們把 SDK 包成一個函式。它接收 2.4 節說的**通用格式 messages**，自己轉成 Gemini 的格式。**全書從現在開始，都透過這個函式跟 LLM 說話。**

```python
def call_llm(messages, temperature=None, max_output_tokens=1024):
    """
    把通用格式的 messages 送給 Gemini，回傳模型的文字回答。
    messages 的格式：[{"role": "system" / "user" / "assistant", "content": "文字"}, ...]
    """
    system_text = None
    contents = []

    # 把通用格式轉成 Gemini 的格式
    for msg in messages:
        if msg["role"] == "system":
            # system 不放進 contents，而是另外交給 system_instruction
            system_text = msg["content"]
        else:
            # Gemini 把 assistant 叫做 model
            role = "model" if msg["role"] == "assistant" else "user"
            contents.append({"role": role, "parts": [{"text": msg["content"]}]})

    response = client.models.generate_content(
        model=MODEL_NAME,
        contents=contents,
        config=types.GenerateContentConfig(
            system_instruction=system_text,
            temperature=temperature,
            max_output_tokens=max_output_tokens,
        ),
    )

    # 回答是空的時候 response.text 會是 None，統一轉成空字串比較好處理
    return response.text or ""


# 試用看看
messages = [
    {"role": "system", "content": "你是金門大學的校園小助理，回答一律使用繁體中文，而且不超過兩句話。"},
    {"role": "user", "content": "你好，你是誰？"},
]
print(call_llm(messages))
```

**逐段解說：**

- **參數**：
  - `messages`：通用格式的訊息 list，每則訊息是一個有 `role` 和 `content` 的 dict。
  - `temperature=None`：預設是 `None`，代表「不指定，用模型自己的預設值」。需要穩定輸出時，呼叫端再傳 `temperature=0`。
  - `max_output_tokens=1024`：預設給 1024，對一般回答很夠用，也能防止費用失控。
- **for 迴圈轉換格式**：
  - 遇到 `system`：存到 `system_text`，之後交給 `system_instruction`。
  - 遇到 `assistant`：改名成 `model`。
  - 其他（`user`）：照原樣。
  - 每則訊息都包成 Gemini 要的 `{"role": ..., "parts": [{"text": ...}]}`。SDK 接受這種 dict 寫法，跟程式 2-1 手寫的 JSON 結構一模一樣。
- **`response.text or ""`**：如果回答是空的（例如被安全機制擋下，或 token 被思考用光），`response.text` 會是 `None`。`None or ""` 的結果是 `""`，這樣呼叫端拿到的永遠是字串，不用擔心 `None` 造成錯誤。

**預期輸出：**

```text
你好！我是金門大學的校園小助理，可以幫你查詢校園資訊、課程或生活上的問題。有什麼需要幫忙的嗎？
```

**`call_llm()` 在全書的位置：**

```text
  其他程式（聊天迴圈、工具、Agent⋯⋯）
          │  只用通用格式 messages
          ▼
  ┌──────────────────────┐
  │  call_llm(messages)  │  ← 唯一知道「Gemini 格式長怎樣」的地方
  └──────────────────────┘
          │  轉成 Gemini 格式，透過 SDK 送出
          ▼
     Google Gemini API
```

第 4 章的 `mock_llm(messages)` 也會用**一模一樣的呼叫方式**，這樣沒有 API key 的讀者，只要把 `call_llm` 換成 `mock_llm` 就能繼續。

## 【常見錯誤】

| 錯誤情況 | 原因 | 解決方式 |
|---------|------|---------|
| 狀態碼 `400`，訊息有 `API_KEY_INVALID` | 金鑰錯誤、複製時少了字或多了空白 | 回 AI Studio 重新複製，更新 Colab 密鑰 |
| 狀態碼 `404`，或 SDK 說模型找不到 | `MODEL_NAME` 拼錯，或模型已停用 | 到官方 Models 頁面確認最新名稱 |
| 狀態碼 `429` | 太快送太多請求，超過免費額度 | 等一分鐘再試；程式 2-4 這種迴圈不要跑太多次 |
| `KeyError: 'candidates'` | 請求失敗了，回應裡是錯誤訊息，不是答案 | 先印出 `response.status_code` 和 `response.json()` 看錯誤內容 |
| `KeyError: 'parts'` | 回答被切斷或是空的 | 檢查 `finishReason`；用 `.get()` 安全取值 |
| 回答講到一半就斷掉 | `maxOutputTokens` 太小，`finishReason` 是 `MAX_TOKENS` | 調大 `maxOutputTokens` |
| `ImportError` 或 `AttributeError: module 'google.genai'...` | SDK 沒裝、太舊，或裝成舊版套件 | 重跑 `!pip install -q -U google-genai`，再到選單「執行階段 → 重新啟動工作階段」 |
| REST 寫 `max_output_tokens`、SDK 寫 `maxOutputTokens` | 搞混命名規則 | REST 用駝峰式 `maxOutputTokens`；Python SDK 用蛇形 `max_output_tokens` |
| 調 temperature 沒有效果 | 用的是 Gemini 3.6 以後或 Gemini 4 系列 | 這些模型會忽略 temperature，本書用 `gemini-3.5-flash-lite` |

## 【本章小結】

1. 呼叫 LLM API ＝ 送出 HTTP POST 請求（網址＋標頭裡的金鑰＋JSON 主體），收回 JSON 回應。
2. 回答藏在 `candidates[0].content.parts[0].text`；`finishReason` 告訴你為什麼停；`usageMetadata` 告訴你用了多少 token（也就是花了多少錢）。
3. 訊息有三種角色：`system`（開發者設定）、`user`（使用者）、`assistant`（模型，Gemini 叫 `model`）。Gemini 的 system 放在獨立的 `system_instruction` 欄位。
4. `temperature` 控制隨機程度，`max_output_tokens` 控制回答長度上限；思考 token 也算在長度上限裡。
5. SDK 把手寫的 HTTP 請求包裝起來，但背後送的是同一份 JSON。全書從此透過 `call_llm(messages)` 呼叫 LLM。
