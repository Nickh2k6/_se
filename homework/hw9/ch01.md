# 第 1 章　LLM 是什麼

## 【本章重點】

**LLM 本質上是一個「超強的文字接龍機器」**：它讀進一段文字，算出「下一個字最可能是什麼」，挑一個接上去，再重複這個動作，直到整段回答寫完。
它挑字是**照機率抽**的，所以同一個問題每次回答可能不同；它只在乎「接起來順不順」，不在乎「內容對不對」，所以會一本正經地亂講（幻覺）。
也因為它只會「接文字」，它**不知道現在幾點、不能真的計算、查不到你的課表** —— 這正是本書後面要幫它加上「工具」的原因。

---

## 【為什麼需要這一章】

第 0 章把 Colab 和 API key 準備好了，照理說可以直接開始呼叫 API。但如果你還不知道 LLM 是怎麼「想」的，很快就會遇到這些困惑：

- 「我問它今天星期幾，它為什麼回答錯？」
- 「同樣的問題問兩次，為什麼答案不一樣？是不是程式寫錯了？」
- 「它講得頭頭是道，為什麼查證後發現是假的？」

這些都不是 bug，而是 LLM 運作方式的**必然結果**。先搞懂它「會什麼、不會什麼」，後面每一章為什麼要加那一層，你才會覺得理所當然。

---

## 【觀念解說】

### 1.1 超強的文字接龍

**LLM（Large Language Model，大型語言模型）**：一種用海量文字訓練出來的程式，它唯一的核心能力是「**根據前面的文字，預測下一個字**」。

- **Large（大型）**：指模型很大，裡面有數十億到上兆個可以調整的數字（叫做**參數，parameter**），也指它讀過的文字非常多。
- **Language Model（語言模型）**：一個能算出「一段文字接下來最可能出現什麼」的模型。

**比喻：文字接龍遊戲。**

小時候玩過的文字接龍：前一個人說「今天天氣」，你接「很好」。你為什麼接「很好」而不是「冰箱」？因為你從小聽過、讀過無數句子，知道「今天天氣」後面最常接「很好」「很熱」「不錯」。

LLM 做的就是同一件事，只是：

| | 你玩文字接龍 | LLM |
|---|---|---|
| 讀過多少文字 | 一輩子聽過、讀過的 | 網路上數以兆計的字 |
| 看前面多少字 | 大概前一兩句 | 可以一次看幾十萬字 |
| 怎麼決定 | 憑感覺 | 算出每個候選字的**機率**，照機率挑 |

**回到技術說明：LLM 產生一段回答的實際流程是這樣：**

```text
  輸入：「金門大學位於」
          │
          ▼
  ┌──────────────────┐
  │       LLM        │  算出「下一個字」每個候選的機率
  └──────────────────┘
          │
          ▼
   金：62%   台：15%   福：8%   ……
          │
          │ 照機率挑一個 → 挑到「金」
          ▼
  新的輸入：「金門大學位於金」  ──┐
                                 │ 把剛挑的字接上去，再丟回 LLM
          ┌──────────────────────┘
          ▼
   門：91%   寧：5%   ……   → 挑到「門」
          ▼
  「金門大學位於金門」 → …… 一直重複，直到模型挑出「結束」記號
```

這種「每次只產生一個字，接上去之後再產生下一個」的方式，叫做**自迴歸生成（autoregressive generation）**。你在 ChatGPT 或 Gemini 網頁上看到答案「一個字一個字跑出來」，就是這個原因 —— 它真的是一個一個算出來的。

> **那它怎麼會「回答問題」？**
> 因為訓練資料裡有大量「問題 → 回答」的文字。模型學到：看到問題之後，最可能接著出現的就是一段回答。
> 模型訓練分成兩階段：先讀海量文字學會「接龍」，叫**預訓練（pre-training）**；再用大量「問答範例」調整它，讓它的接龍習慣變成「像個助理一樣回答」，叫**微調（fine-tuning）**。
> 但不管怎麼調，**它的底層動作從頭到尾都是「預測下一個字」**。

### 1.2 Token 是什麼

前面一直說「下一個字」，其實不太精確。LLM 處理文字的最小單位叫做 **token（詞元）**。

**Token**：模型把文字切成的一小塊一小塊。一個 token 可能是一個完整的英文單字、半個單字、一個中文字、幾個中文字，甚至是一個標點符號。

比喻：就像樂高積木。模型不是一個字母一個字母地看文字，而是先把文字拆成一塊塊「常見的積木」，再用積木來接龍。

```text
  英文：  "unbelievable"  →  [un] [believ] [able]          3 個 token
  中文：  「金門大學」      →  [金門] [大學]  或  [金][門][大][學]
                                ↑ 實際怎麼切，每個模型不一樣
```

**為什麼你要在意 token？因為三件事都用 token 計算：**

1. **費用**：API 是依照 token 數收費的，通常寫成「每一百萬個 token 多少美元」。**你送進去的**（輸入 token）和**模型回答的**（輸出 token）都要算錢，而且輸出通常比較貴。
2. **長度上限**：模型一次能讀的文字有上限，這個上限也是用 token 計算（第 3 章會講的「上下文長度」）。
3. **速度**：回答的 token 越多，生成越久，因為要一個一個算。

> **粗略換算**（只是概念，不同模型差很多）：英文大約每 4 個字母是 1 個 token；中文大約每 1 個字是 1～2 個 token。
> 第 2 章呼叫 API 時，回傳的資料裡會直接告訴你這次用了多少 token，到時候就能看到真實數字。

### 1.3 機率與取樣：為什麼每次回答不一樣

模型算出每個候選 token 的機率之後，要**怎麼挑**呢？有兩種方式：

| 挑法 | 做法 | 結果 |
|------|------|------|
| **永遠挑最高的**（貪婪解碼，greedy decoding） | 每次都挑機率最大的那個 | 每次答案幾乎一樣，但容易死板、重複 |
| **照機率抽**（取樣，sampling） | 機率 40% 的有 40% 機會被抽中，5% 的也有 5% 機會 | 答案有變化、比較自然，但偶爾會抽到奇怪的 |

比喻：**抽籤筒**。機率高的籤放得多，機率低的籤放得少。每次伸手抽一支 —— 大多數時候抽到常見的，但偶爾也會抽到冷門的那支。

大部分 LLM 預設是用「照機率抽」，所以**同樣的問題問兩次，答案不同是正常的**，不是程式出錯。

有一個參數可以調整「抽籤的隨機程度」，叫做 **temperature（溫度）**：

- 溫度**低** → 高機率的籤變得更多、低機率的籤更少 → 答案更穩定、更保守
- 溫度**高** → 每支籤的數量變得比較平均 → 答案更多樣、更有創意，也更容易亂講

第 2 章會在 API 裡實際調整它。下面【動手做】的程式 1-1，就是用 Python 模擬這個抽籤筒。

### 1.4 幻覺：為什麼會一本正經地亂講

**幻覺（hallucination）**：LLM 產生了**聽起來很合理、語氣很肯定，但實際上是錯的或根本不存在**的內容。

例如你問「金門大學資工系的系主任是誰？」，模型可能會很流暢地回答一個名字 —— 但那個名字可能是它「接龍接出來」的，現實中根本不是這個人。

**為什麼會這樣？回到文字接龍的本質：**

```text
  模型在想的是：「這段文字接下來，什麼字最順？」
  模型沒有在想：「這件事是真的嗎？」
```

- 「系主任是」後面，最順的接法是「一個人名」—— 所以它一定會接一個人名。
- 如果訓練資料裡剛好有正確答案，而且出現很多次，它很可能接對。
- 如果訓練資料裡沒有、很少、或過時了，它**還是會接一個聽起來像人名的東西**，因為「不接」在接龍裡是很不順的。

比喻：像一個**很會講話、但不太愛承認自己不知道的同學**。你問他什麼，他都能講得頭頭是道，語氣比誰都肯定 —— 但你不能保證他講的都是對的。

**容易出現幻覺的情況：**

- 冷門的、特定的事實（某個小系所的老師、某條巷子的店）
- 數字、日期、網址、論文標題、程式套件名稱
- 模型訓練之後才發生的事
- 要求它做精確計算

下面【動手做】的程式 1-2 會用一個迷你接龍表，讓你親眼看到「句子很通順，內容卻是錯的」是怎麼發生的。

> **怎麼減少幻覺？** 本書後面會用兩種方法：
> - 第 5～7 章：讓模型用**工具**去查真的資料，而不是憑記憶接龍。
> - 第 10 章：先把相關資料**找出來放進輸入裡**，讓模型照著資料回答（RAG）。

### 1.5 LLM 不會的事

搞懂「它只會接龍」之後，就能理解為什麼有些事它天生做不到：

| LLM 做不到的事 | 原因 | 本書怎麼解決 |
|---------------|------|-------------|
| 不知道**現在幾點、今天幾號** | 模型是一份「訓練完就固定」的檔案，裡面沒有時鐘 | 第 5 章：工具 `get_current_time()` |
| **精確計算**大數字 | 它是在「接數字的字串」，不是在算數 | 第 5 章：工具 `calculator()` |
| 知道**你的課表**、學校的私有資料 | 訓練資料裡根本沒有 | 第 5 章：工具 `get_schedule()` |
| 知道**最新的天氣、新聞** | 訓練資料有**截止日期（knowledge cutoff）**，之後的事它不知道 | 第 5 章：工具 `get_weather()` |
| **記得你上一句說什麼** | 每次呼叫 API 都是獨立的（第 3 章詳細說明） | 第 3 章：自己保存對話 |
| 真的**去做事**（寄信、存檔、查資料庫） | 它只會輸出文字，沒有手 | 第 5 章起：讓它「說」要做什麼，你的程式去做 |

最後一列最重要，請把這句話記起來：

> **LLM 只會產生文字。它不會、也不能自己執行任何東西。**

你可能會想：「可是 ChatGPT 明明可以上網、可以跑程式啊？」那是因為 ChatGPT 這個**產品**在 LLM 外面包了一層程式，幫它去執行。這一層程式要怎麼寫，就是這本書要教你的。

## 【動手做】

本章不需要安裝任何套件，也**不需要 API key**。我們用 Python 內建的 `random` 模組，模擬 LLM「照機率挑下一個字」的過程。

### 程式 1-1：抽籤筒 —— 為什麼每次回答不一樣

```python
import random

# 假設模型讀完「我今天想去」之後，算出下一個詞的機率
next_word_probs = {
    "圖書館": 0.40,
    "海邊": 0.25,
    "吃早餐": 0.20,
    "睡覺": 0.10,
    "火星": 0.05,
}

words = list(next_word_probs.keys())
probs = list(next_word_probs.values())

# 方法一：照機率抽（取樣），模擬同一個問題問 5 次
print("【照機率抽】")
for i in range(5):
    picked = random.choices(words, weights=probs, k=1)[0]
    print(f"第 {i + 1} 次：我今天想去{picked}")

# 方法二：永遠挑機率最高的（貪婪解碼）
print("\n【永遠挑最高的】")
best = max(next_word_probs, key=next_word_probs.get)
for i in range(5):
    print(f"第 {i + 1} 次：我今天想去{best}")
```

**逐段解說：**

- `next_word_probs`：一個 dict，代表模型讀完「我今天想去」之後算出的機率表。真正的 LLM 會對**幾萬到幾十萬個** token 各算一個機率，這裡只放 5 個示意。所有機率加起來是 1（也就是 100%）。
- `words`、`probs`：把 dict 拆成兩個 list，一個放候選詞，一個放對應的機率，因為下一行的 `random.choices()` 要這樣傳。
- `random.choices(words, weights=probs, k=1)`：照 `weights` 指定的比例抽 1 個（`k=1`）。它回傳的是 list，所以用 `[0]` 取出第一個。這就是「抽籤筒」。
- `max(next_word_probs, key=next_word_probs.get)`：找出 dict 中「值最大」的那個 key，也就是機率最高的詞。不管跑幾次，結果都一樣。

**預期輸出（「照機率抽」的部分每次執行都會不同）：**

```text
【照機率抽】
第 1 次：我今天想去圖書館
第 2 次：我今天想去吃早餐
第 3 次：我今天想去圖書館
第 4 次：我今天想去海邊
第 5 次：我今天想去火星

【永遠挑最高的】
第 1 次：我今天想去圖書館
第 2 次：我今天想去圖書館
第 3 次：我今天想去圖書館
第 4 次：我今天想去圖書館
第 5 次：我今天想去圖書館
```

**觀察重點：**

- 「照機率抽」多跑幾次，「圖書館」最常出現，但其他詞也會出現 —— 這就是 LLM 每次回答不一樣的原因。
- 偶爾會抽到只有 5% 機率的「火星」。機率低不代表不會發生，這也是模型偶爾冒出奇怪答案的原因之一。
- 「永遠挑最高的」每次都一樣，很穩定，但也很死板。

### 程式 1-2：迷你接龍機 —— 親眼看見幻覺

這段程式做一個超迷你的「語言模型」：它只知道「看到某個詞，下一個詞可能是什麼」，然後一路接龍，直到接到「結束」為止。

```python
import random

# 迷你接龍表：看到左邊的詞，下一個詞可能是右邊這些（附上機率）
# 注意：這張表只學到「哪些詞常接在一起」，完全沒有記錄「哪些事是真的」
next_table = {
    "<開始>":     {"金門大學": 1.0},
    "金門大學":   {"資工系": 0.6, "圖書館": 0.4},
    "資工系":     {"的系主任是": 0.5, "位於": 0.5},
    "圖書館":     {"位於": 1.0},
    "的系主任是": {"王大明": 0.5, "陳志明": 0.5},
    "位於":       {"金寧鄉": 0.7, "台北市": 0.3},
    "王大明":     {"<結束>": 1.0},
    "陳志明":     {"<結束>": 1.0},
    "金寧鄉":     {"<結束>": 1.0},
    "台北市":     {"<結束>": 1.0},
}


def generate_sentence():
    """從 <開始> 一路接龍，直到接到 <結束> 為止"""
    current = "<開始>"
    sentence = ""
    while True:
        # 查表：目前這個詞後面，可以接哪些詞、機率多少
        options = next_table[current]
        # 照機率抽一個當作下一個詞
        current = random.choices(list(options.keys()), weights=list(options.values()))[0]
        # 抽到結束記號就停止
        if current == "<結束>":
            break
        # 把抽到的詞接到句子後面，然後繼續接下一個
        sentence += current
    return sentence


# 讓迷你模型造 5 個句子
for i in range(5):
    print(f"第 {i + 1} 句：{generate_sentence()}")
```

**逐段解說：**

- `next_table`：一張「接龍表」。外層的 key 是「目前這個詞」，內層 dict 是「下一個詞可能是什麼、機率多少」。`<開始>` 和 `<結束>` 是特殊記號，代表句子的開頭和結尾 —— 真正的 LLM 也有類似的特殊 token。
- 表裡的人名「王大明」「陳志明」都是**虛構的**，「台北市」也是錯的（金門大學在金門縣金寧鄉）。但這張表**沒有任何地方記錄真假**，它只記錄「哪些詞常接在一起」。
- `generate_sentence()`：
  - 從 `<開始>` 出發。
  - `while True` 迴圈每一輪做三件事：**查表 → 照機率抽一個 → 接到句子後面**。這就是 1.1 節講的自迴歸生成。
  - 抽到 `<結束>` 就跳出迴圈，回傳整句話。
- 最後的 `for` 迴圈讓它造 5 個句子。

**預期輸出（每次執行都會不同）：**

```text
第 1 句：金門大學資工系的系主任是王大明
第 2 句：金門大學圖書館位於金寧鄉
第 3 句：金門大學資工系位於台北市
第 4 句：金門大學資工系的系主任是陳志明
第 5 句：金門大學圖書館位於金寧鄉
```

**觀察重點：**

- **每一句都很通順**，文法完全正確，語氣也很肯定。
- 但「系主任是王大明」是編的、「位於台北市」是錯的。這就是**幻覺**：模型只保證「接得順」，不保證「是真的」。
- 同一個問題（「資工系的系主任是誰」），它有時說王大明、有時說陳志明 —— 照機率抽，答案就會變。

**這個迷你模型和真正的 LLM 差在哪？**

| | 程式 1-2 的迷你模型 | 真正的 LLM |
|---|---|---|
| 接龍表從哪來 | 我們手寫的 dict | 從海量文字中**自動學出來**，存在數十億個參數裡 |
| 看前面多少 | 只看前一個詞 | 看前面**全部**的文字（最多到上下文長度上限） |
| 候選詞有多少 | 每次 1～2 個 | 每次幾萬到幾十萬個 token |

規模差了好幾億倍，所以真正的 LLM 寫出來的文字聰明得多。但**核心動作完全一樣：查機率、抽一個、接上去、再重複**。在這個過程中，沒有任何一步在「查證事實」。

## 【常見錯誤】

| 錯誤觀念 | 正確理解 |
|---------|---------|
| 「同一個問題答案不一樣，是程式壞了」 | 模型預設照機率抽字，答案有變化是正常的。要更穩定可以調低 temperature（第 2 章）。 |
| 「它講得這麼肯定，一定是對的」 | 語氣肯定和內容正確**完全無關**。人名、數字、日期、網址一定要查證。 |
| 「問它今天幾號，它應該知道」 | 模型裡沒有時鐘，只能憑訓練資料猜。要正確時間必須用工具（第 5 章）。 |
| 「LLM 可以直接幫我寄信、存檔」 | LLM 只會產生文字。能「做事」的是包在外面的程式（第 5 章起）。 |
| 「token 就是字數」 | token 是模型切出來的小塊，和字數不完全對應。費用和長度上限都是用 token 算的。 |
| 「`random.choices` 回傳的是一個字串」 | 它回傳的是 **list**，要用 `[0]` 取出裡面的元素。 |

---

## 【本章小結】

1. LLM 是「超強的文字接龍機器」：根據前面的文字算出下一個 token 的機率，挑一個接上去，重複到結束（自迴歸生成）。
2. Token 是模型處理文字的最小單位；API 的費用、長度上限都用 token 計算，輸出 token 通常比輸入貴。
3. 模型預設是「照機率抽」，所以同一個問題答案會不同；temperature 可以調整隨機程度。
4. 模型只在乎「接得順」，不檢查「是不是真的」，因此會產生幻覺。
5. LLM 只會產生文字：不知道現在時間、不能精確計算、查不到私有資料、也無法自己執行任何動作 —— 後面的章節就是要一步步補上這些能力。
