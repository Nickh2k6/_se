# 第 11 章　回頭看框架

## 【本章重點】

**框架沒有魔法：它們做的事，就是你在前面十章親手寫過的東西。** `call_llm()`、工具宣告、`run_tool()`、`run_agent()` 迴圈、停止條件、人工確認、紀錄、記憶、RAG，每一個主流 Agent 框架都有對應的零件，只是名字不同、包得比較好。
因為你知道底層怎麼運作，選框架時你會知道它「幫你做了什麼」，出問題時你會知道「該往哪一層找」。
這一章先畫出全書的完整層級圖，再對照 LangChain、OpenAI Agents SDK、Claude Agent SDK 和 Google 的做法，最後用 LangChain 把校園小助理重寫一次，看看框架省下了多少程式碼。

## 【為什麼需要這一章】

回頭看第 10 章的程式 10-0：光是「準備環境」就有將近 600 行。這些程式碼你都看懂了，但想一想：

- 如果要換成 OpenAI 或 Claude 的模型，`call_llm_tools()` 裡的格式轉換要全部重寫。
- 每加一個工具，就要同時改函式、`TOOLS`、`TOOL_DECLARATIONS` 三個地方。
- 想要更好的紀錄、想把 Agent 部署成網頁服務、想讓好幾個 Agent 分工合作⋯⋯每一樣都要自己從頭寫。

這些事情**每個做 Agent 的人都會遇到**，所以有人把它們整理成框架。但如果你一開始就用框架，你會覺得它很神奇，卻不知道它在做什麼；出錯時，錯誤訊息裡的名詞你一個都看不懂。

**現在你已經親手寫過每一層了。** 這一章要做的，就是把你寫過的東西，和框架裡的名字一一對上。

### 11.2 框架在做什麼

**框架（framework）**：別人寫好的一整套程式架構，規定好「零件要怎麼組合」，你只要把自己的部分（工具、prompt）填進去。

**比喻：自己組電腦 vs 買品牌電腦。**

- 前十章，你是**自己組電腦**：挑 CPU、裝主機板、接線，每一個零件都摸過。組起來很累，但你知道每個零件在哪、壞了要換哪一個。
- 框架像**品牌電腦**：打開就能用，很方便。而因為你組過電腦，你看得懂它的規格表，也知道「記憶體不夠」是什麼意思。

**你寫過的零件，在框架裡叫什麼？**

| 你寫過的 | 做什麼 | 框架裡常見的名稱 |
|---------|-------|---------------|
| `call_llm()` / `call_llm_tools()` | 呼叫模型、轉換格式 | Model、Chat model、LLM client |
| 通用格式 `messages` | 統一不同廠商的訊息格式 | Message 類別（HumanMessage、AIMessage⋯⋯） |
| `TOOL_DECLARATIONS`（手寫 JSON Schema） | 告訴模型有哪些工具 | **從函式的型別提示和 docstring 自動產生** |
| `TOOLS` ＋ `run_tool()` | 依名稱執行工具 | Tool executor、Tool node |
| `run_agent()` 的 while 迴圈 | 思考 → 行動 → 觀察 | Agent、Runner、Agent loop |
| `max_steps` | 最多跑幾圈 | `recursion_limit`、`max_turns`、`max_iterations` |
| 安全版 `run_tool()` | 錯誤交還給模型 | 工具錯誤處理（tool error handling） |
| `ask_user_confirm()` | 危險動作先問人 | Human-in-the-loop、permissions、approval |
| `AGENT_LOG` | 記錄每一步 | Tracing（追蹤）、callbacks、hooks |
| `history` | 短期記憶 | Session、thread、checkpointer |
| `remember()` ＋ 記憶檔 | 長期記憶 | Memory、store |
| `search_notes()` | RAG 的檢索 | Retriever、vector store |
| `mock_llm()` / `stubborn_llm_tools()` | 用假模型測試 | Fake model、test model |

其中最能省事的一項是**自動產生工具宣告**。第 6 章你手寫了一大段 `TOOL_DECLARATIONS`，框架通常只要你寫好函式：

```python
def get_schedule(day: str) -> dict:
    """查詢學生某一天的課表。day 是星期一到星期日其中之一。"""
    ...
```

框架會讀取函式名稱（→ `name`）、docstring（→ `description`）、參數的型別提示 `day: str`（→ `parameters`），自動組出你在第 6 章手寫的那份 JSON Schema。**它背後送給模型的，還是同樣的東西。**

> **型別提示（type hint）**：在參數或回傳值後面加上 `: str`、`-> dict` 這種標記，說明它應該是什麼型別。Python 執行時不會檢查它，但框架可以讀取它來產生 schema。本書前面的程式為了簡單沒有寫，用框架時就很重要了。

### 11.3 LangChain

**LangChain**：最早、也最廣為人知的 LLM 應用框架之一，支援非常多家的模型和工具。目前的版本用 `create_agent()` 建立 Agent，背後的迴圈由同一家公司的 **LangGraph** 負責執行。

```python
# 參考程式碼（程式 11-1 會實際執行）
from langchain.agents import create_agent

agent = create_agent(
    model="google_genai:gemini-3.5-flash-lite",   # 「廠商:模型名稱」
    tools=[get_current_time, get_schedule],       # 直接傳入 Python 函式
    system_prompt="你是金門大學校園小助理……",
)
result = agent.invoke({"messages": [{"role": "user", "content": "明天有什麼課？"}]})
```

| 你寫過的 | LangChain 對應 |
|---------|---------------|
| `call_llm_tools()` | `model="google_genai:..."`（換廠商只要改這個字串） |
| `TOOL_DECLARATIONS` | 從函式自動產生（也可以用 `@tool` 裝飾器） |
| `run_agent()` | `create_agent()` ＋ `agent.invoke()` |
| `messages` | 輸入和輸出都是 `{"messages": [...]}` |
| `max_steps` | `recursion_limit`（在 `invoke` 的 config 裡設定） |
| `ask_user_confirm()` | `HumanInTheLoopMiddleware` |
| 短期記憶 `history` | checkpointer ＋ thread |

**中介軟體（middleware）**：LangChain 用來「在 Agent 迴圈的某個時間點插入自己的程式」的機制。例如 `HumanInTheLoopMiddleware` 會在執行指定的工具前暫停，等人確認，這就是你在第 9 章寫的 `ask_user_confirm()`。

### 11.4 OpenAI Agents SDK

**OpenAI Agents SDK**：OpenAI 官方的 Agent 框架（套件名稱 `openai-agents`），設計得很精簡，核心只有幾個概念。

```python
# 參考程式碼（需要 OpenAI 的 API key，本書不執行）
from agents import Agent, Runner

agent = Agent(name="Assistant", instructions="You are a helpful assistant")

result = Runner.run_sync(agent, "Write a haiku about recursion in programming.")
print(result.final_output)
```

| 你寫過的 | OpenAI Agents SDK 對應 |
|---------|---------------------|
| `SYSTEM_PROMPT` | `Agent(instructions=...)` |
| `run_agent()` | `Runner.run()` / `Runner.run_sync()` |
| 最終回答 | `result.final_output` |
| `TOOLS` ＋ `TOOL_DECLARATIONS` | 用裝飾器把 Python 函式變成 function tool，自動產生 schema |
| `max_steps` | `max_turns` |
| 第 9 章的安全檢查 | **Guardrails**（護欄：檢查輸入或輸出是否合規）、human in the loop |
| `history` | **Sessions** |
| `AGENT_LOG` | **Tracing** |
| （本書沒有） | **Handoffs**：一個 Agent 把工作轉交給另一個 Agent |

### 11.5 Claude Agent SDK（以及 Claude API 的 Tool Runner）

Anthropic 提供兩種不同層級的工具，名字很像，但範圍差很多：

| | Claude API 的 **Tool Runner** | **Claude Agent SDK** |
|---|---|---|
| 套件 | `anthropic`（一般的 Claude API SDK） | `claude-agent-sdk` |
| 幫你做什麼 | 只幫你跑「呼叫 → 執行工具 → 送回結果」的迴圈 | 整套 Claude Code 的 Agent：迴圈、內建工具、權限、session、hooks、subagents |
| 工具 | 只有你自己定義的工具 | 內建讀寫檔案、執行指令、搜尋網路等工具，再加上你的工具 |
| 對應本書 | 大約等於第 7 章的 `run_agent()` | 第 7～10 章全部，再多很多 |

**Tool Runner** 的寫法和本書的思路幾乎一模一樣：用 `@beta_tool` 裝飾器定義工具（自動產生 schema），交給 `tool_runner()` 跑迴圈：

```python
# 參考程式碼（需要 Anthropic 的 API key，本書不執行）
import anthropic
from anthropic import beta_tool

client = anthropic.Anthropic()

@beta_tool
def get_weather(location: str, unit: str = "celsius") -> str:
    """Get current weather for a location.

    Args:
        location: City and state, e.g., San Francisco, CA.
        unit: Temperature unit, either "celsius" or "fahrenheit".
    """
    return f"72°F and sunny in {location}"

# The tool runner handles the agentic loop automatically
runner = client.beta.messages.tool_runner(
    model="claude-opus-5-5",
    max_tokens=16000,
    tools=[get_weather],
    messages=[{"role": "user", "content": "What's the weather in Paris?"}],
)

for message in runner:
    print(message)
```

**Claude Agent SDK** 則是把 Claude Code（Anthropic 的程式開發 Agent）整個包成函式庫。它的設定項目幾乎可以逐條對應到本書：

```python
# 參考程式碼（需要 Anthropic 的 API key，本書不執行）
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions


async def main():
    options = ClaudeAgentOptions(
        system_prompt="You are an expert Python developer",
        permission_mode="acceptEdits",
    )

    async for message in query(prompt="Create a Python web server", options=options):
        print(message)


asyncio.run(main())
```

| 你寫過的 | Claude Agent SDK 對應（`ClaudeAgentOptions` 的欄位） |
|---------|------------------------------------------------|
| `SYSTEM_PROMPT` | `system_prompt` |
| `max_steps` | `max_turns` |
| `DANGEROUS_TOOLS` ＋ `ask_user_confirm()` | `permission_mode`（例如 `"default"`、`"acceptEdits"`、`"plan"`）、`allowed_tools`（不用問就能執行的工具）、`can_use_tool`（自訂的確認函式） |
| `AGENT_LOG`、在某個時間點插入檢查 | hooks |
| `history` | sessions（可以接續、分支） |
| 自訂工具 `TOOLS` | `@tool` 裝飾器 ＋ `create_sdk_mcp_server()`，再用 `mcp_servers` 交給 Agent |
| 讀寫檔案、執行指令 | 內建工具（Read、Write、Edit、Bash、Grep、WebSearch、WebFetch 等） |

注意 `permission_mode`：它就是第 9 章「工具分級」的正式版，決定哪些動作可以直接執行、哪些要先問人。一個能讀寫檔案、執行指令的 Agent，權限設定比校園小助理重要得多。

> Anthropic 還有一種 **Managed Agents**：連迴圈和執行工具的環境都由 Anthropic 的伺服器代管，你只要設定 Agent、送出訊息。這是比 Agent SDK 再往上一層的「全託管」服務。

### 11.6 Google 的新做法：Interactions API 與 ADK

**Interactions API**：第 2 章提過，這是 Google 現在推薦新專案使用的 Gemini API。和本書使用的 `generateContent` 最大的差別是：**伺服器可以幫你保存對話**。

```text
  generateContent（本書）                    Interactions API
  ─────────────────────────────             ─────────────────────────────
  每次把整段 messages 送出去                  第一次呼叫後拿到一個 interaction id
  （第 3 章：無狀態，程式自己記）               下一次只要帶上 previous_interaction_id
                                            伺服器就會接上之前的對話
```

但它的本質和第 3 章說的一樣：**模型每次還是要讀完整段對話**，只是那個 list 從你的程式搬到了 Google 的伺服器上保管。如果不希望資料留在伺服器上，也可以設定 `store=False`，改回由自己保存、每次全部送出。

**ADK（Agent Development Kit）**：Google 官方的 Agent 框架（套件名稱 `google-adk`），和 Gemini 整合得最好。

```python
# 參考程式碼（本書不執行，完整用法請看 ADK 官方文件）
from google.adk import Agent
from google.adk.tools import google_search

agent = Agent(
    name="researcher",
    model="gemini-flash-latest",
    instruction="Help users research topics thoroughly.",
    tools=[google_search],
)
```

ADK 的結構和其他框架很像：`instruction` 對應 `SYSTEM_PROMPT`，`tools` 可以放 Python 函式或 Google 提供的內建工具（例如上面的 Google 搜尋），另外有 Runner 負責執行迴圈、Session 負責保存對話。

### 11.7 什麼時候該用框架、什麼時候自己寫就好

| 情況 | 建議 | 原因 |
|------|------|------|
| 學習 Agent 怎麼運作 | **自己寫** | 就是這本書在做的事 |
| 只需要呼叫一次模型（翻譯、摘要、分類） | **自己寫** | 一個 `call_llm()` 就夠了，用框架反而複雜 |
| 流程固定的 workflow（第 7 章） | **自己寫**或輕量工具 | 步驟寫死就好，不需要完整的 Agent 框架 |
| 需要支援好幾家廠商的模型 | **用框架** | 格式轉換框架都做好了 |
| 需要部署、追蹤、多個 Agent 合作 | **用框架** | 這些基礎建設自己寫很花時間 |
| 要讀寫檔案、執行程式的 Agent | **用框架**（例如 Claude Agent SDK） | 內建工具和權限控制都很成熟，自己寫容易有安全漏洞 |

**不管用不用框架，前十章學到的東西都用得上**：

- Agent 不照預期行動時，你會去看它**送了什麼 messages**、**工具說明寫得清不清楚**。
- 費用太高時，你知道是**每一圈都重送整段對話**造成的。
- 設定權限時，你知道**prompt 擋不住提示注入**，危險的動作要用程式把關。

### 11.8 下一步可以學什麼

**MCP（Model Context Protocol，模型上下文協定）**：一個開放的標準，規定「AI 應用程式」和「外部工具、資料來源」之間要怎麼溝通。

比喻：**USB 接頭**。以前每個工具都要為每家 AI 框架各寫一套接法；有了 MCP，工具只要做成一個「MCP 伺服器」，任何支援 MCP 的 Agent（Claude、ChatGPT、各種框架）都能直接接上使用。

回想第 6 章的 `TOOL_DECLARATIONS`：每換一家模型，工具宣告的格式就要改一次。MCP 就是把「工具宣告＋執行」標準化，讓工具可以到處重複使用。11.5 節的 Claude Agent SDK 用 `create_sdk_mcp_server()` 定義自訂工具，用的就是 MCP。

**其他值得繼續探索的方向：**

| 主題 | 是什麼 | 和本書的關係 |
|------|-------|------------|
| 多 Agent 系統（multi-agent） | 好幾個 Agent 分工：一個負責規劃，其他負責查資料、寫報告 | 把 `run_agent()` 當成另一個 Agent 的工具 |
| 評估（evaluation） | 用一批測試問題，系統性地檢查 Agent 答得對不對 | 第 8 章的「固執假模型」測試是它的雛形 |
| 向量搜尋（embedding） | 用意思而不是字面來搜尋 | 第 10 章 10.7 節 |
| 串流（streaming） | 回答一個字一個字送回來，使用者不用乾等 | 第 1 章的自迴歸生成 |
| 部署（deployment） | 把 Agent 包成網頁或聊天機器人給別人用 | 把 `chat_agent()` 的 `input()` 換成網頁表單 |

```python
    "星期四": [{"time": "08:10-10:00", "course": "離散數學"}],
    "星期五": [{"time": "09:10-12:00", "course": "程式設計實習"}],
    "星期六": [],
    "星期日": [],
}


# ===== 工具：只要寫好函式、型別提示和 docstring =====
def get_current_time() -> str:
    """取得台灣現在的日期、星期與時間。不知道今天星期幾時，要先使用這個工具。"""
    now = datetime.now(ZoneInfo("Asia/Taipei"))
    return f"{now.strftime('%Y-%m-%d')} {WEEKDAYS[now.weekday()]} {now.strftime('%H:%M')}"


def get_schedule(day: str) -> dict:
    """查詢學生某一天的課表。day 必須是星期一到星期日其中之一，例如「星期三」。"""
    if day not in FAKE_SCHEDULE:
        return {"error": f"day 必須是星期一到星期日，收到的是：{day}"}
    return {"day": day, "courses": FAKE_SCHEDULE[day]}


# ===== 建立 Agent：模型、工具、system prompt =====
agent = create_agent(
    model="google_genai:gemini-3.5-flash-lite",
    tools=[get_current_time, get_schedule],
    system_prompt="你是金門大學校園小助理。一律使用繁體中文，回答簡短。工具查得到的資訊不要自己猜。",
)

# ===== 執行 =====
result = agent.invoke({"messages": [{"role": "user", "content": "明天有什麼課？"}]})

# 印出整個過程（每一則訊息）
for message in result["messages"]:
    message.pretty_print()
```

**逐段解說：**

- **`os.environ["GOOGLE_API_KEY"] = ...`**：`os.environ` 是**環境變數**（作業系統層級的設定值），LangChain 的 Gemini 套件會自動讀取 `GOOGLE_API_KEY`。值是從 Colab 密鑰讀出來的，所以**金鑰仍然沒有寫在程式裡**。
- **兩個工具**：和第 5 章的工具做同樣的事，差別是加上了**型別提示**（`day: str`、`-> dict`），而且 docstring 寫成給模型看的說明。11.2 節說過，LangChain 會用這些資訊**自動產生工具宣告**。
- **`create_agent(...)`**：
  - `model="google_genai:gemini-3.5-flash-lite"`：「廠商:模型名稱」的格式。想換成別家的模型，改這個字串、裝對應的套件就好（對照第 2 章：本書要改的是整個 `call_llm()`）。
  - `tools=[...]`：直接傳入函式。**不用寫 `TOOLS`、`TOOL_DECLARATIONS`、`run_tool()`**。
  - `system_prompt=...`：對應 `SYSTEM_PROMPT`。
- **`agent.invoke(...)`**：對應 `run_agent()`。輸入是 `{"messages": [...]}`，格式就是本書的通用 messages。
- **`message.pretty_print()`**：把每一則訊息漂亮地印出來，你會看到使用者的問題、模型的工具請求、工具結果、最終回答，就像第 7 章 `run_agent()` 印出的每一步。

**預期輸出（以 2026-11-27 星期五執行為例；實際格式依 LangChain 版本可能略有不同）：**

```text
================================ Human Message =================================

明天有什麼課？
================================== Ai Message ==================================
Tool Calls:
  get_current_time (xxxxxxxx)
 Call ID: xxxxxxxx
  Args:
================================= Tool Message =================================
Name: get_current_time

2026-11-27 星期五 21:30
================================== Ai Message ==================================
Tool Calls:
  get_schedule (xxxxxxxx)
 Call ID: xxxxxxxx
  Args:
    day: 星期六
================================= Tool Message =================================
Name: get_schedule

{"day": "星期六", "courses": []}
================================== Ai Message ==================================

```

**和本書的 `run_agent()` 對照：**

```text
  LangChain 印出的                     本書第 7 章 run_agent() 印出的
  ─────────────────────────────       ─────────────────────────────
  Human Message                       你：明天有什麼課？
  Ai Message → Tool Calls             [第 1 步] 行動：get_current_time()
  Tool Message                                  觀察：2026-11-27 星期五 21:30
  Ai Message → Tool Calls             [第 2 步] 行動：get_schedule(day="星期六")
  Tool Message                                  觀察：{"day": "星期六", "courses": []}
  Ai Message                          [第 3 步] 最終回答：明天是星期六……
```

**完全是同一個流程。** 「Ai Message」就是第 6 章的 assistant 紙條（`tool_calls`），「Tool Message」就是第 6 章的 `{"role": "tool", ...}`。

**觀察重點：**

- 這段程式扣掉假資料，**核心只有十幾行**。第 10 章同樣的功能，準備環境就將近 600 行。
- 但**少寫的部分並沒有消失**，而是 LangChain 幫你寫好了：格式轉換（第 2、6 章）、工具宣告（第 6 章）、迴圈（第 7 章）。
- 這個版本還**沒有**第 8～10 章的東西：錯誤處理怎麼設定？停止條件呢？危險工具的人工確認？記憶？這些 LangChain 都有對應的功能（11.3 節的表格），但要你知道它們存在、知道為什麼需要，才會去設定。**這正是前十章要讓你知道的事。**

## 【常見錯誤】

| 錯誤情況 | 原因 | 解決方式 |
|---------|------|---------|
| 以為用了框架就不用懂底層 | 框架只是把底層包起來 | 出錯時還是要看 messages、工具說明、停止原因 |
| 框架產生的工具說明不清楚，模型不會用 | 函式沒寫 docstring 或型別提示 | docstring 寫給模型看：做什麼、什麼時候用、參數格式 |
| 網路上的範例跑不起來 | 框架版本更新很快，舊教學的寫法已經改了 | 以官方文件為準，注意文章的日期 |
| 把 Tool Runner 和 Claude Agent SDK 搞混 | 名字很像 | Tool Runner 只跑迴圈；Agent SDK 是整套 Claude Code，有內建工具 |
| 用了框架之後就不設定停止條件和權限 | 以為框架的預設值一定安全 | 檢查框架的步數上限、權限設定，危險工具一定要人工確認 |
| 把 API key 直接寫在 `os.environ[...] = "AIza..."` | 換了寫法就忘了安全規則 | 一樣從 Colab 密鑰讀取 |
| 只需要呼叫一次模型，卻用了整套 Agent 框架 | 殺雞用牛刀 | 簡單的任務自己寫一個 `call_llm()` 就好 |

## 【本章小結】

1. 全書像一棟五層樓：呼叫 API → 對話記憶 → 結構化輸出 → 工具呼叫 → Agent 迴圈，再加上可靠、安全、記憶三個強化；每一層都是因為下面那層不夠用才出現。
2. 框架做的事，就是把你親手寫過的零件包裝起來：模型介面、自動產生工具宣告、Agent 迴圈、步數上限、人工確認、追蹤、記憶、RAG。
3. LangChain（`create_agent`）、OpenAI Agents SDK（`Agent` ＋ `Runner`）、Claude Agent SDK（`query` ＋ `ClaudeAgentOptions`）、Google ADK 的名字不同，但都能對應到本書的 `call_llm_tools()`、`TOOLS`、`run_agent()`、`max_steps`、`ask_user_confirm()`、`history`。
4. 學習、單次呼叫、固定流程適合自己寫；多廠商、部署、多 Agent、需要成熟權限控制的情況適合用框架。
5. MCP 把「工具」標準化，讓同一個工具可以接到任何支援它的 Agent；下一步可以學多 Agent、評估、向量搜尋與部署。
