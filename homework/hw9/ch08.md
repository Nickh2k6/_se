# 第 8 章　讓 Agent 更可靠

## 【本章重點】

真實世界裡，**工具一定會出錯**，模型也可能**繞圈圈停不下來**。可靠的 Agent 要做到三件事：
① 工具出錯時**不要當掉**，而是把錯誤訊息當成「觀察結果」交還給模型，讓它自己修正；
② 設好**停止條件**：正常回答、超過最大步數、連續失敗太多次、花費超過預算，任何一個成立就停；
③ **記錄每一步**的動作和 token 用量，出問題時才查得出原因，也才知道花了多少錢。

---

## 【為什麼需要這一章】

第 7 章的 `run_agent()` 在「一切順利」的時候表現很好。但試試這個問題：

```text
你：100 除以 0 是多少？
[第 1 步] 思考：這需要計算，我用計算機算。
          行動：calculator(expression="100 / 0")
Traceback (most recent call last):
  ...
ZeroDivisionError: division by zero
```

**整個 Agent 當掉了。** 使用者什麼回答都沒拿到，前面花掉的 token 也白費了。

第 5 章的常見錯誤表列過好幾種會讓程式當掉的狀況：模型拼錯工具名稱（`KeyError`）、參數名稱寫錯（`TypeError`）、參數值不合法（`ValueError`）。在 Agent 裡這些問題更嚴重，因為它一個問題可能要用好幾次工具，**每一次都可能出錯**。

另外，第 7 章的保險只有 `max_steps`。但如果工具壞掉了，模型一直重試，就會白白跑滿 10 圈、花 10 次錢。我們也完全不知道一題到底花了多少 token。

這一章要讓 Agent 在**不順利**的時候，也能好好地處理。

## 【觀念解說】

### 8.1 工具出錯，整個 Agent 就當掉

先看錯誤是怎麼一路傳上來的：

```text
  run_agent()
     └─ run_tool("calculator", {"expression": "100 / 0"})
           └─ calculator("100 / 0")
                 └─ eval("100 / 0")   💥 ZeroDivisionError
                        │
                        ▼ 例外沒有人接住，一路往上丟
  run_agent() 也跟著中斷，使用者什麼都沒拿到
```

**例外（exception）**：程式執行時發生錯誤，Python 會「丟出（raise）」一個例外。如果沒有用 `try/except` 接住，它會一路往上傳，最後讓整個程式停止。

### 8.2 把錯誤訊息交還給模型，讓它自我修正

**比喻：實習生遇到問題時，不要當場崩潰，而是回來報告。**

你請實習生去影印室印資料，結果影印機卡紙。

- ❌ 不好的實習生：愣在影印機前面，什麼都不做，你也不知道發生了什麼事。
- ✅ 好的實習生：回來說「影印機卡紙了」。你可以決定「那用另一台」或「改天再印」。

**回到技術說明**：在 `run_tool()` 裡用 `try/except` 接住所有例外，把錯誤變成一段**文字**，當作工具的執行結果送回給模型：

```text
  run_tool("get_weather", {"city": "金門縣"})
        │
        ▼ get_weather 丟出例外
  except 接住 → 回傳字串「錯誤：ValueError: 沒有「金門縣」的天氣資料，目前只能查：金門、台北」
        │
        ▼ 當成「觀察結果」加進 messages
  模型看到錯誤訊息 → 再思考：「喔，要用『金門』」→ 行動：get_weather(city="金門") ✓
```

這就是**自我修正（self-correction）**：模型看到自己的錯誤，換一種做法再試一次。這和第 4 章的 `ask_json()`（JSON 格式錯了就請模型重寫）是同一個想法，只是現在用在工具上。

**好的錯誤訊息要讓模型「知道怎麼改」：**

| 錯誤訊息 | 模型看了之後 |
|---------|------------|
| `錯誤` | 不知道發生什麼事，可能一直用同樣的參數重試 |
| `錯誤：KeyError: '金門縣'` | 知道「金門縣」不行，但不知道該用什麼 |
| `錯誤：沒有「金門縣」的天氣資料，目前只能查：金門、台北` | ✅ 馬上知道要改用「金門」 |

所以除了在 `run_tool()` 接住例外，**工具本身的錯誤訊息也要寫得清楚**。本章會把 `get_weather()` 改成這種寫法。

> **本書的約定**：工具的執行結果如果以「**錯誤：**」開頭，就代表這次執行失敗了。第 5 章的 `calculator()` 遇到非法字元時，回傳的也是「錯誤：」開頭的文字，剛好符合這個約定。

### 8.3 最大步數 `max_steps`

第 7 章已經有 `max_steps`，這裡說明它為什麼重要、該設多少。

**模型什麼時候會停不下來？**

- 工具一直失敗，模型一直重試。
- 模型「想太多」，查了又查，一直覺得資訊不夠。
- 兩個工具的結果互相矛盾，模型來回確認。
- 模型忘了自己已經查過，重複查同樣的東西。

**該設多少？** 看你的 Agent 一般需要幾步。校園小助理大部分問題 1～4 步就能完成，設 `10` 已經很寬鬆。設太小，正常的問題也會被中斷；設太大，出問題時會浪費很多錢。

### 8.4 停止條件

一個可靠的 Agent 至少要有這四種停止條件：

| 停止條件 | 什麼時候成立 | 結果 |
|---------|------------|------|
| ① 正常結束 | 模型的回應沒有工具請求 | ✅ 回傳最終回答 |
| ② 超過最大步數 | `step >= max_steps` | ⚠️ 回傳道歉訊息 |
| ③ 連續失敗太多次 | 工具**連續**失敗 `max_failures` 次 | ⚠️ 回傳道歉訊息（可能是工具壞了） |
| ④ 超過 token 預算 | 累積 token 數超過 `token_budget` | ⚠️ 回傳道歉訊息（避免花太多錢） |

```text
                       ┌─────────────┐
               ┌─────▶ │  呼叫 LLM    │
               │       └──────┬──────┘
               │              │ 累加 token
               │              ▼
               │       沒有工具請求？ ──是──▶ ① 正常結束 ✅
               │              │ 否
               │              ▼
               │       超過 token 預算？ ──是──▶ ④ 停止 ⚠️
               │              │ 否
               │              ▼
               │       執行工具（失敗不會當掉，錯誤變成觀察結果）
               │              │
               │              ▼
               │       連續失敗太多次？ ──是──▶ ③ 停止 ⚠️
               │              │ 否
               │              ▼
               │       超過最大步數？ ──是──▶ ② 停止 ⚠️
               │              │ 否
               └──────────────┘
```

**為什麼是「連續」失敗？** 偶爾失敗一次、模型修正後成功，這是正常的自我修正，不應該停。只有**一直**失敗（例如工具的伺服器掛了），才代表再試也沒用。所以成功一次，計數就歸零。

### 8.5 成本控制

第 3 章算過「對話越長越貴」。Agent 更明顯，因為：

- **一個問題要呼叫好幾次 LLM**（第 7 章：一題 1～4 次）。
- **每一圈的 messages 都比上一圈長**（多了工具請求和結果），而且全部重送。
- **工具宣告每次都要送**（第 6 章），也算輸入 token。

```text
  第 1 圈送出：system + 工具宣告 + 問題                           ≈ 600 token
  第 2 圈送出：system + 工具宣告 + 問題 + 紙條① + 結果①           ≈ 750 token
  第 3 圈送出：system + 工具宣告 + 問題 + 紙條①② + 結果①②         ≈ 950 token
                                                       累積 ≈ 2300 token
```

所以要**記錄每一次呼叫的 token 用量**。Gemini 的回應裡就有（第 2 章的 `usage_metadata`），我們讓 `call_llm_tools()` 把它一起回傳：

```python
{"text": ..., "tool_calls": [...], "raw": ..., "usage": {"input": 612, "output": 25}}
```

- `input`：輸入 token（`prompt_token_count`）
- `output`：輸出 token（`candidates_token_count` ＋ `thoughts_token_count`，思考也要算錢）

`run_agent()` 把每一圈的用量加起來，超過 `token_budget` 就停止。

> **換算成錢**：API 的價格通常寫成「每一百萬個 token 多少美元」，輸入和輸出分開計價。實際價格請查官方的 Pricing 頁面。本章範例會用**假設的價格**示範計算方式，不代表真實費用。

### 8.6 加上紀錄（log）

**紀錄（log，也叫日誌）**：程式執行時，把「什麼時間、做了什麼、結果如何」一筆一筆記下來。

比喻：飛機的**黑盒子**。平常沒人去看，但出事的時候，靠它才能知道是哪一步出了問題。

Agent 特別需要紀錄，因為**步驟是模型自己決定的**。使用者抱怨「它給了錯的答案」時，你必須能回頭查：

- 模型在第幾步用了哪個工具？參數是什麼？
- 工具回傳了什麼？有沒有出錯？
- 每一步花了多少 token？

本章用一個全域的 list `AGENT_LOG` 記錄最近一次 `run_agent()` 的每一個事件，最後可以印出摘要，也可以存成 JSON 檔。

```python
def calculator(expression):
    """計算數學算式，例如 "(3 + 4) * 2"。只允許數字和 + - * / ( ) ."""
    allowed = set("0123456789+-*/(). ")
    if not set(expression) <= allowed:
        return "錯誤：算式只能包含數字和 + - * / ( ) ."
    if "**" in expression:
        return "錯誤：不支援次方運算"
    return eval(expression, {"__builtins__": {}}, {})

def call_llm_tools(messages, temperature=None, max_output_tokens=1024):
    """
    原生工具呼叫版的 call_llm：把通用格式的 messages 連同工具宣告一起送給 Gemini。
    回傳 dict：{"text": 文字回答, "tool_calls": [{"name": ..., "args": {...}}], "raw": 模型的原始回應內容}
    """
    system_text = None
    contents = []

    for msg in messages:
        if msg["role"] == "system":
            system_text = msg["content"]

        elif msg["role"] == "user":
            contents.append(types.Content(role="user", parts=[types.Part.from_text(text=msg["content"])]))

        elif msg["role"] == "assistant":
            if msg.get("raw") is not None:
                contents.append(msg["raw"])
            else:
                parts = []
                if msg.get("content"):
                    parts.append(types.Part.from_text(text=msg["content"]))
                for call in msg.get("tool_calls", []):
                    parts.append(types.Part(function_call=types.FunctionCall(name=call["name"], args=call["args"])))
                contents.append(types.Content(role="model", parts=parts))

        elif msg["role"] == "tool":
            part = types.Part.from_function_response(name=msg["name"], response={"result": msg["content"]})
            last = contents[-1] if contents else None
            if last is not None and last.role == "user" and last.parts[0].function_response is not None:
                last.parts.append(part)
            else:
                contents.append(types.Content(role="user", parts=[part]))

    response = client.models.generate_content(
        model=MODEL_NAME,
        contents=contents,
        config=types.GenerateContentConfig(
            system_instruction=system_text,
            temperature=temperature,
            max_output_tokens=max_output_tokens,
            tools=[types.Tool(function_declarations=TOOL_DECLARATIONS)],
        ),
    )

    content = response.candidates[0].content
    text = ""
    tool_calls = []
    if content is not None and content.parts:
        for part in content.parts:
            if part.function_call is not None:
                tool_calls.append({"name": part.function_call.name, "args": dict(part.function_call.args or {})})
            elif part.text and not part.thought:
                text += part.text

    return {"text": text, "tool_calls": tool_calls, "raw": content}


def mock_next_action(question, used):
    """假的 LLM 的「大腦」：根據問題裡的關鍵字，決定下一步要用哪個工具"""
    day = None
    for d in WEEKDAYS:
        if d in question:
            day = d
            break

    need_time = any(k in question for k in ["幾點", "幾號", "星期幾", "時間", "日期"])
    if "課" in question and day is None:
        need_time = True
    if need_time and "get_current_time" not in used:
        return {"tool": "get_current_time", "args": {}}

    if "課" in question and "get_schedule" not in used:
        if day is None:
            time_text = used.get("get_current_time", "")
            for i, d in enumerate(WEEKDAYS):
                if d in time_text:
                    day = WEEKDAYS[(i + 1) % 7] if "明天" in question else d
                    break
        if day is not None:
            return {"tool": "get_schedule", "args": {"day": day}}

    if any(k in question for k in ["天氣", "雨", "騎車", "傘"]) and "get_weather" not in used:
        city = "台北" if "台北" in question else "金門"
        return {"tool": "get_weather", "args": {"city": city}}

    question_math = question.replace("乘以", "*").replace("除以", "/").replace("加", "+").replace("減", "-")
    match = re.search(r"\d[\d\.\s\(\)]*[\+\-\*/][\d\.\s\+\-\*/\(\)]*\d", question_math)
    if match and "calculator" not in used:
        return {"tool": "calculator", "args": {"expression": match.group()}}
```

### 程式 8-2：安全版的 `run_tool()` 與更好的錯誤訊息

```python
def run_tool(name, args):
    """
    安全版：依照工具名稱找到函式並執行，把結果轉成字串回傳。
    任何錯誤都不會讓程式當掉，而是回傳「錯誤：」開頭的說明文字，交給模型處理。
    """
    # 情況一：模型要求的工具不存在
    if name not in TOOLS:
        return f"錯誤：沒有叫做「{name}」的工具。可以使用的工具有：{', '.join(TOOLS)}"

    try:
        result = TOOLS[name](**args)
    except TypeError as e:
        # 情況二：參數名稱或數量不對，例如把 day 寫成 date
        return f"錯誤：{name} 的參數不正確（{e}）"
    except Exception as e:
        # 情況三：工具執行時發生其他錯誤
        return f"錯誤：{type(e).__name__}: {e}"

    if isinstance(result, str):
        return result
    return json.dumps(result, ensure_ascii=False)


def get_weather(city):
    """查詢某個城市今天和明天的天氣；查不到時丟出清楚的錯誤訊息"""
    if city not in FAKE_WEATHER:
        available = "、".join(FAKE_WEATHER.keys())
        raise ValueError(f"沒有「{city}」的天氣資料，目前只能查：{available}")
    return {"city": city, **FAKE_WEATHER[city]}


# 重要：TOOLS 裡存的還是「舊的」get_weather，要更新成新的
TOOLS["get_weather"] = get_weather

print(run_tool("get_schedule", {"date": "星期一"}))
print(run_tool("get_schedule", {"day": "明天"}))
print(run_tool("get_weather", {"city": "金門縣"}))
print(run_tool("get_weather", {"city": "金門"})[:40] + "……")
```

**逐段解說：**

- **情況一：工具不存在**。先用 `if name not in TOOLS` 檢查，回傳的訊息裡**列出所有可用的工具**，模型看到就知道正確的名稱。`', '.join(TOOLS)`：對 dict 做 join 會用它的 key。
- **`try` 區塊**：只包住「執行工具」這一行，範圍越小，越清楚錯誤是哪裡來的。
- **情況二：`except TypeError`**。呼叫函式時參數名稱不對（`date` 而不是 `day`）或少給參數，Python 會丟出 `TypeError`。我們特別把它挑出來，告訴模型「參數不正確」。
- **情況三：`except Exception`**。`Exception` 是幾乎所有例外的「祖先」，可以接住任何其他錯誤（`ZeroDivisionError`、`ValueError`、網路錯誤⋯⋯）。注意 `except` 的順序：**比較具體的寫在前面**，`Exception` 放最後。
- **回傳的字串都以「錯誤：」開頭**，符合 8.2 節的約定。
- **新版 `get_weather()`**：查不到城市時改成 `raise ValueError`，而且訊息裡**列出可以查的城市**。現在有安全版的 `run_tool()` 統一接住例外，工具本身只要專心寫出清楚的錯誤訊息就好。
- **`TOOLS["get_weather"] = get_weather`**：這行很容易忘記！`TOOLS` 是在程式 8-0 建立的，裡面存的是**當時的** `get_weather` 函式。重新定義 `get_weather` 只是讓這個名字指向新函式，`TOOLS` 裡的舊函式不會自動更新。
- **`run_agent()` 不用改**：它呼叫的是 `run_tool`，Python 在執行時才會去找 `run_tool` 這個名字目前指向哪個函式，所以會自動用到新版。

**預期輸出：**

### 程式 8-4：讓模型回報 token 用量

我們升級 `call_llm_tools()` 和 `mock_llm_tools()`，讓回傳的 dict 多一個 `usage` 欄位。**原本的三個欄位完全不變**，所以舊的程式照樣能用。

```python
def call_llm_tools(messages, temperature=None, max_output_tokens=1024):
    """
    原生工具呼叫版的 call_llm：把通用格式的 messages 連同工具宣告一起送給 Gemini。
    回傳 dict：{"text": ..., "tool_calls": [...], "raw": ..., "usage": {"input": 輸入 token, "output": 輸出 token}}
    """
    system_text = None
    contents = []

    for msg in messages:
        if msg["role"] == "system":
            system_text = msg["content"]

        elif msg["role"] == "user":
            contents.append(types.Content(role="user", parts=[types.Part.from_text(text=msg["content"])]))

        elif msg["role"] == "assistant":
            if msg.get("raw") is not None:
                contents.append(msg["raw"])
            else:
                parts = []
                if msg.get("content"):
                    parts.append(types.Part.from_text(text=msg["content"]))
                for call in msg.get("tool_calls", []):
                    parts.append(types.Part(function_call=types.FunctionCall(name=call["name"], args=call["args"])))
                contents.append(types.Content(role="model", parts=parts))

        elif msg["role"] == "tool":
            part = types.Part.from_function_response(name=msg["name"], response={"result": msg["content"]})
            last = contents[-1] if contents else None
            if last is not None and last.role == "user" and last.parts[0].function_response is not None:
                last.parts.append(part)
            else:
                contents.append(types.Content(role="user", parts=[part]))

    response = client.models.generate_content(
        model=MODEL_NAME,
        contents=contents,
        config=types.GenerateContentConfig(
            system_instruction=system_text,
            temperature=temperature,
            max_output_tokens=max_output_tokens,
            tools=[types.Tool(function_declarations=TOOL_DECLARATIONS)],
        ),
    )

    content = response.candidates[0].content
    text = ""
    tool_calls = []
    if content is not None and content.parts:
        for part in content.parts:
            if part.function_call is not None:
                tool_calls.append({"name": part.function_call.name, "args": dict(part.function_call.args or {})})
            elif part.text and not part.thought:
                text += part.text

    # ===== 新增：整理 token 用量（欄位可能是 None，所以用 or 0） =====
    meta = response.usage_metadata
    usage = {
        "input": (meta.prompt_token_count or 0) if meta else 0,
        "output": ((meta.candidates_token_count or 0) + (meta.thoughts_token_count or 0)) if meta else 0,
    }

    return {"text": text, "tool_calls": tool_calls, "raw": content, "usage": usage}


def mock_llm_tools(messages, temperature=None, max_output_tokens=1024):
    """假的原生工具呼叫：參數和回傳格式都和 call_llm_tools() 一樣（token 用量是用字數粗估的）"""
    question = ""
    question_index = 0
    for i in range(len(messages) - 1, -1, -1):
        if messages[i]["role"] == "user":

            question_index = i
            break

    used = {}
    for msg in messages[question_index + 1:]:
        if msg["role"] == "tool":
            used[msg["name"]] = msg["content"]

    action = mock_next_action(question, used)

    # ===== 新增：粗估 token 用量 —— 假設 1 個字約 1 個 token，再加上工具宣告約 300 個 =====
    input_tokens = 300 + sum(len(str(m.get("content", ""))) for m in messages)

    if "tool" in action:
        thought = MOCK_THOUGHTS.get(action["tool"], "")
        usage = {"input": input_tokens, "output": len(thought) + 20}
        return {"text": thought, "tool_calls": [{"name": action["tool"], "args": action["args"]}], "raw": None, "usage": usage}

    usage = {"input": input_tokens, "output": len(action["answer"])}
    return {"text": action["answer"], "tool_calls": [], "raw": None, "usage": usage}
```

### 程式 8-5：可靠版 `run_agent()` —— 停止條件、成本控制、紀錄

這段只是定義函式，**不需要 API key**。

```python
# 最近一次 run_agent() 的紀錄（黑盒子）
AGENT_LOG = []


def log_event(step, kind, **details):
    """在 AGENT_LOG 裡記下一筆事件"""
    record = {
        "time": datetime.now(ZoneInfo("Asia/Taipei")).strftime("%H:%M:%S"),
        "step": step,
        "kind": kind,
    }
    record.update(details)
    AGENT_LOG.append(record)


def run_agent(user_input, max_steps=10, max_failures=3, token_budget=20000):
    """
    可靠版 Agent 主迴圈。
    停止條件：① 模型給出最終回答 ② 超過 max_steps 步
             ③ 工具連續失敗 max_failures 次 ④ 累積 token 超過 token_budget
    """
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT + "\n\n" + AGENT_PROMPT},
        {"role": "user", "content": user_input},
    ]
    AGENT_LOG.clear()            # 每次執行都從空的紀錄開始
    log_event(0, "start", question=user_input)

    total_tokens = 0             # 累積的 token 數
    failures = 0                 # 工具「連續」失敗的次數
    step = 0

    while step < max_steps:
        step += 1

        # ① 思考
        response = llm_tools(messages, temperature=0)
        step_tokens = response["usage"]["input"] + response["usage"]["output"]
        total_tokens += step_tokens
        log_event(step, "llm", tokens=step_tokens, total_tokens=total_tokens)

        # 停止條件 ①：正常結束
        if not response["tool_calls"]:
            print(f"[第 {step} 步] 最終回答：{response['text'].strip()}")
            print(f"[統計] 共 {step} 步，累積 {total_tokens} token")
            log_event(step, "answer", text=response["text"])
            return response["text"]

        # 停止條件 ④：超過 token 預算（在執行工具之前檢查）
        if total_tokens > token_budget:
            print(f"[停止] 累積 {total_tokens} token，超過預算 {token_budget}。")
            log_event(step, "stop", reason="token_budget")
            return "（抱歉，這個問題需要的資源超過上限，我先停下來了。）"

        if response["text"].strip():
            print(f"[第 {step} 步] 思考：{response['text'].strip()}")
        else:
            print(f"[第 {step} 步]")

        messages.append({
            "role": "assistant",
            "content": response["text"],
            "tool_calls": response["tool_calls"],
            "raw": response["raw"],
        })

        # ② 行動 ＋ ③ 觀察
        for call in response["tool_calls"]:
            print(f"          行動：{format_call(call['name'], call['args'])}")
            result = run_tool(call["name"], call["args"])
            print(f"          觀察：{result}")
            messages.append({"role": "tool", "name": call["name"], "content": result})

            # 計算連續失敗次數：失敗就加 1，成功就歸零
            ok = not result.startswith("錯誤：")
            failures = 0 if ok else failures + 1
            log_event(step, "tool", name=call["name"], args=call["args"], ok=ok, result=result[:100])

        # 停止條件 ③：工具連續失敗太多次
        if failures >= max_failures:
            print(f"[停止] 工具已經連續失敗 {failures} 次。")
            log_event(step, "stop", reason="too_many_failures")
            return "（抱歉，工具一直發生錯誤，請稍後再試。）"

    # 停止條件 ②：超過最大步數
    print(f"[停止] 已經跑了 {max_steps} 步，還沒有得到最終回答。")
    log_event(step, "stop", reason="max_steps")
    return "（抱歉，這個問題太複雜了，我沒辦法在限定的步數內完成。）"


print("可靠版 run_agent() 準備完成！")
```

**逐段解說：**

- **`AGENT_LOG`**：全域的 list，存放最近一次執行的所有事件。每次 `run_agent()` 開始時用 `.clear()` 清空。
- **`log_event(step, kind, **details)`**：
  - `**details` 用在**定義**函式時，意思是「其他所有具名參數，全部收集成一個 dict」。例如 `log_event(1, "tool", name="calculator", ok=False)`，`details` 就是 `{"name": "calculator", "ok": False}`。（第 5 章的 `func(**args)` 是**呼叫**時把 dict 展開，這裡剛好相反。）
  - `record.update(details)`：把 `details` 的內容合併進 `record`。
- **新的參數**：`max_failures=3`、`token_budget=20000`。都有預設值，所以 `run_agent("問題")` 這種舊的寫法照樣能用。
- **兩個計數器**：
  - `total_tokens`：每一圈把 `usage` 加進去。
  - `failures`：**連續**失敗次數。`failures = 0 if ok else failures + 1`：成功就歸零，失敗就加 1（8.4 節說明了為什麼是「連續」）。
- **四個停止條件**對照 8.4 節的流程圖：
  - **①** 沒有工具請求 → 正常回答，並印出統計。
  - **④** 超過預算 → 在**執行工具之前**檢查，避免再多花錢。
  - **③** 連續失敗 → 在這一圈的所有工具執行完之後檢查。
  - **②** 超過步數 → `while` 迴圈自然結束。
- **判斷成功或失敗**：`result.startswith("錯誤：")`，靠的就是 8.2 節的約定。
- **`result[:100]`**：紀錄裡只存結果的前 100 個字，避免紀錄變得太大。

**預期輸出：**

```text
可靠版 run_agent() 準備完成！
```

### 程式 8-6：測試保險機制 —— 用「固執的假模型」

停止條件 ②③④ 在正常情況下很少觸發，要怎麼測試？我們寫一個**專門用來測試**的假模型：它非常固執，**永遠**要求查時間，從來不給最終回答。這段**不需要 API key**。

```python
def stubborn_llm_tools(messages, temperature=None, max_output_tokens=1024):
    """測試用的假模型：永遠要求 get_current_time，從來不給最終回答"""
    input_tokens = 300 + sum(len(str(m.get("content", ""))) for m in messages)
    return {
        "text": "我再查一次時間。",
        "tool_calls": [{"name": "get_current_time", "args": {}}],
        "raw": None,
        "usage": {"input": input_tokens, "output": 30},
    }


def broken_time():
    """模擬壞掉的工具：每次都連不上伺服器"""
    raise ConnectionError("連不上時間伺服器")


# 暫時換成固執的假模型（測完再換回來）
real_llm_tools = llm_tools
llm_tools = stubborn_llm_tools

print("===== 測試 ②：超過最大步數 =====")
run_agent("現在幾點？", max_steps=3)

print("\n===== 測試 ③：工具連續失敗 =====")
real_time_tool = TOOLS["get_current_time"]
TOOLS["get_current_time"] = broken_time        # 把工具換成壞掉的版本
run_agent("現在幾點？", max_steps=10, max_failures=3)
TOOLS["get_current_time"] = real_time_tool     # 換回正常的工具

print("\n===== 測試 ④：超過 token 預算 =====")
run_agent("現在幾點？", max_steps=10, token_budget=2000)

# 換回原本的模型
llm_tools = real_llm_tools
print("\n目前 llm_tools 指向：", llm_tools.__name__)
```

**逐段解說：**

- **`stubborn_llm_tools()`**：回傳格式和 `call_llm_tools()` 完全一樣（四個欄位都有），但不管 messages 裡有什麼，永遠要求 `get_current_time`。token 用量一樣用字數粗估，所以 messages 越長，用量越大。
- **`broken_time()`**：一個永遠丟出 `ConnectionError`（連線錯誤）的函式，模擬「時間伺服器掛了」。
- **三個測試**：
  - **測試 ②**：`max_steps=3`，固執的模型跑滿 3 步就被停下來。
  - **測試 ③**：把 `TOOLS` 裡的 `get_current_time` 暫時換成 `broken_time`，每次都失敗，連續 3 次後停止。測完一定要**換回來**。
  - **測試 ④**：`token_budget=2000`，因為每一圈 messages 都變長，累積的 token 越跑越多（613 → 1254 → 1923 → 2620），第 4 次呼叫後就超過預算。注意第 4 步**沒有被印出來**：超過預算的檢查在執行工具之前，所以這一步的工具沒有執行。
- **暫時替換、測完換回**：和第 7 章程式 7-3 一樣的技巧。這種「用假的東西代替真的，來測試程式邏輯」的做法，在軟體測試裡很常見，第 0 章說的 mock 就是這個意思。

### 程式 8-7：查看紀錄、估算費用

先用正常的模型跑一題，再查看黑盒子裡的紀錄：

```python
run_agent("明天有什麼課？要帶傘嗎？")
```

## 【常見錯誤】

| 錯誤情況 | 原因 | 解決方式 |
|---------|------|---------|
| 工具出錯，整個 Agent 當掉 | `run_tool()` 沒有 `try/except` | 使用安全版 `run_tool()`，把錯誤變成文字交給模型 |
| 改了工具函式，Agent 卻還在用舊的 | `TOOLS` 裡存的是舊函式 | 重新定義後要更新 `TOOLS["名稱"] = 新函式` |
| 改了 `call_llm_tools()`，卻沒有效果 | `llm_tools` 還指向舊的函式 | 重新執行 `llm_tools = mock_llm_tools if USE_MOCK else call_llm_tools` |
| 模型一直用同樣的錯誤參數重試 | 錯誤訊息太模糊，模型不知道怎麼改 | 錯誤訊息要說明「哪裡錯、可以怎麼改」（例如列出可用的城市） |
| `except Exception` 寫在 `except TypeError` 前面 | 順序錯了，`TypeError` 永遠不會被單獨處理 | 具體的例外寫前面，`Exception` 放最後 |
| 用 `except:`（什麼都不寫）接住所有東西 | 連使用者按「停止」都會被接住，程式停不下來 | 至少寫 `except Exception` |
| 偶爾失敗一次就停止 | 用的是「總失敗次數」而不是「連續失敗次數」 | 成功時把計數歸零 |
| 測試用的假工具／假模型忘了換回來 | 暫時替換後沒有還原 | 先存到變數（`real_...`），測完一定換回去 |
| `KeyError: 'usage'` | 自己寫的假模型少了 `usage` 欄位 | 所有 `llm_tools` 的回傳格式都要一致：`text`、`tool_calls`、`raw`、`usage` |

---

## 【本章小結】

1. 工具出錯時不要讓 Agent 當掉：安全版 `run_tool()` 接住所有例外，回傳「錯誤：」開頭的文字，當作觀察結果交還給模型。
2. 模型看到清楚的錯誤訊息，能自己換參數重試（**自我修正**）；錯誤訊息要寫明「哪裡錯、怎麼改」。
3. 可靠的 Agent 有四種停止條件：正常回答、超過最大步數、工具連續失敗太多次、超過 token 預算。
4. Agent 的成本會隨步數快速累積；在 `call_llm_tools()` 回傳 `usage`，由 `run_agent()` 累加並控制預算。
5. 用 `AGENT_LOG` 記錄每一步的動作、結果和 token 用量，出問題時才查得到原因；保險機制可以用「固執的假模型」來測試。
