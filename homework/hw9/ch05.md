# 第 5 章　讓 LLM 使用工具（上）手刻版

## 【本章重點】

**LLM 自己不會執行任何東西。它只會「說」要用哪個工具、參數是什麼；真正去「做」的，是你的程式。**
這一章完全不用 API 的特殊功能，只靠 prompt 讓模型輸出 `{"tool": ..., "args": ...}`，再由程式解析、執行對應的 Python 函式，最後把結果送回給模型，讓它根據真實資料回答。
這個「模型說 → 程式做 → 結果送回」的流程，就是所有 AI Agent 的核心。

---

## 【為什麼需要這一章】

第 4 章結束時，我們的程式已經能「讀懂」模型的判斷：

```text
模型輸出：{"intent": "schedule", "day": "星期五", "reply": "我幫你查星期五的課表。"}
程式判斷：→ 要去查「星期五」的課表
```

但程式**只是知道**要查課表，並沒有真的去查。模型也還是不知道你星期五有什麼課。而且第 1 章列出的問題一個都還沒解決：

| 問模型 | 模型的困境 |
|-------|----------|
| 「現在幾點？」 | 模型裡沒有時鐘 |
| 「12345 × 6789 等於多少？」 | 它是在「接數字」，不是在算數，可能算錯 |
| 「星期五有什麼課？」 | 你的課表不在它的訓練資料裡 |
| 「金門明天會下雨嗎？」 | 訓練資料有截止日期，不知道最新天氣 |

第 4 章程式 4-5 還留了一個伏筆：使用者問「明天」，模型填不出星期幾，因為它根本不知道今天是哪一天。

這一章要補上最後一步：**讓程式真的去「做」，再把結果交還給模型。**

---

## 【觀念解說】

### 5.1 問題：模型知道「要做什麼」，但沒有「手」

回顧第 4 章的流程，其實已經走到一半了：

```text
  使用者：星期五有什麼課？
      │
      ▼
  模型：{"intent": "schedule", "day": "星期五"}     ← 第 4 章做到這裡
      │
      ▼
  程式：知道要查星期五的課表 …… 然後呢？           ← 第 5 章要補上
```

缺的兩塊是：

1. 一個真的能「查課表」的 Python 函式。
2. 把查到的結果交還給模型，讓它組織成一句好回答。

### 5.2 核心觀念：模型是「下指令的人」，程式是「動手的人」

**工具（tool）**：一個你寫好的 Python 函式，並且「告訴模型它的存在」，讓模型可以要求使用它。

**工具呼叫（tool calling，也叫 function calling，函式呼叫）**：模型在回答中指定「我要用某個工具、參數是什麼」，由程式去執行，再把結果交還給模型的整個過程。

**比喻：坐在辦公室裡、沒有手的顧問。**

想像一位非常博學的顧問，但他**沒有手、也不能離開座位**。他身邊有一位助理。

- 客人問顧問：「我星期五有什麼課？」
- 顧問自己不知道，於是寫一張紙條給助理：「**請幫我查課表，日期：星期五。**」
- 助理拿著紙條，去櫃子裡翻出課表，抄下結果，拿回來給顧問。
- 顧問看完結果，對客人說：「你星期五早上 9 點有程式設計實習。」

| 比喻 | 實際上是 |
|------|---------|
| 顧問 | LLM |
| 寫紙條 | 模型輸出 `{"tool": "get_schedule", "args": {"day": "星期五"}}` |
| 助理 | 你的 Python 程式 |
| 櫃子裡的課表 | 工具函式 `get_schedule()` 和它的資料 |
| 抄下結果拿回去 | 把執行結果加進 `messages`，再呼叫一次 LLM |

**回到技術說明，資料的流動是這樣的：**

```text
  ┌────────┐ ①問題  ┌───────────────┐ ②messages ┌────────┐
  │ 使用者 │ ─────▶ │               │ ────────▶ │        │
  │        │        │               │ ③「請用    │  LLM   │
  │        │        │  你的 Python  │ ◀──────── │        │
  │        │        │     程式      │ get_schedule│        │
  │        │        │               │  星期五」  │        │
  │        │        │               │            │        │
  │        │        │  ④ 解析 JSON  │            │        │
  │        │        │  ⑤ 執行函式 ─────────┐    │        │
  │        │        │               │      ▼    │        │
  │        │        │               │ ┌──────────────┐   │
  │        │        │               │ │get_schedule()│   │
  │        │        │  ⑥ 拿到結果 ◀───│  （工具）    │   │
  │        │        │               │ └──────────────┘   │
  │        │        │               │ ⑦結果加進  │        │
  │        │        │               │  messages  │        │
  │        │        │               │ ────────▶  │        │
  │        │ ⑨回答  │               │ ⑧最終回答  │        │
  │        │ ◀───── │               │ ◀────────  │        │
  └────────┘        └───────────────┘            └────────┘
```

請注意圖中的關鍵：**LLM 從頭到尾都沒有碰到 `get_schedule()`。** 它只在第 ③ 步「說」了一段文字，第 ⑤ 步的執行完全是你的程式做的。

這件事非常重要，因為它代表：

- **模型能做什麼，完全由你決定。** 你沒寫成工具的事情，它就做不到。
- **執行前，你的程式有機會檢查。** 模型想用危險的工具時，你可以攔下來（第 9 章）。
- **工具可以是任何 Python 程式**：查資料庫、呼叫別的 API、讀檔案⋯⋯模型都不需要知道裡面怎麼實作。

### 5.3 準備工具

校園小助理的四個工具：

| 工具名稱 | 參數 | 回傳 | 資料來源 |
|---------|------|------|---------|
| `calculator` | `expression`：算式字串 | 計算結果（數字） | Python 計算 |
| `get_current_time` | 無 | 「2026-11-27 星期五 21:30」這樣的字串 | 電腦時鐘（台灣時區） |
| `get_schedule` | `day`：星期一～星期日 | 那天的課程列表（dict） | 假的課表 `FAKE_SCHEDULE` |
| `get_weather` | `city`：城市名稱 | 今天和明天的天氣（dict） | 假的天氣 `FAKE_WEATHER` |

課表和天氣用 Python dict 模擬。等你學會整個機制之後，把 dict 換成真的資料庫或氣象 API，模型那一側完全不用改。

> **關於 `calculator` 的安全性**：Python 有一個 `eval()` 函式可以把字串當成程式執行，例如 `eval("1 + 2")` 會得到 `3`。但如果有人傳進去的是 `"__import__('os').system('rm -rf /')"`，就會執行危險的指令！
> 所以我們的 `calculator` **先檢查算式只包含數字和 `+ - * / ( ) .`**，不符合就拒絕。記住這個原則：**工具收到的參數來自模型，而模型的輸入可能來自任何人，所以參數一定要檢查。** 第 9 章會再深入討論。

### 5.4 工具清單：用 dict 把名稱對應到函式

模型輸出的是**字串** `"get_schedule"`，但程式要執行的是**函式** `get_schedule`。怎麼從字串找到函式？用一個 dict：

```python
TOOLS = {
    "calculator": calculator,
    "get_current_time": get_current_time,
    "get_schedule": get_schedule,
    "get_weather": get_weather,
}
```

```text
  模型說："get_schedule"  ──查 TOOLS──▶  get_schedule（函式本身）  ──加上參數執行──▶  結果
```

第 4 章學過「函式可以存進變數」（`llm = call_llm`），這裡是同一個觀念：函式也可以當作 dict 的值。

### 5.5 用 prompt 教模型「怎麼寫紙條」

模型不會自動知道有哪些工具，我們要在 system prompt 裡告訴它。寫在一個新的變數 `TOOL_PROMPT` 裡，跟 `SYSTEM_PROMPT` 組合使用（第 4 章說過，格式規定和角色規則分開寫）。

`TOOL_PROMPT` 要說清楚：

1. **有哪些工具**、每個工具做什麼、參數格式是什麼。
2. **要用工具時**，輸出 `{"tool": "工具名稱", "args": {參數}}`。
3. **可以直接回答時**，輸出 `{"answer": "回答內容"}`。
4. **工具結果長什麼樣子**：程式會用 `[工具結果]` 開頭的訊息送回去。
5. **一個完整的範例。**

模型每一次的輸出，只會是這兩種之一：

```text
  {"tool": "get_schedule", "args": {"day": "星期五"}}    ← 我需要資料，請幫我執行工具
  {"answer": "你星期五早上有程式設計實習。"}              ← 我可以回答了
```

### 5.6 解析 → 執行 → 送回

工具結果要怎麼送回去？手刻版沒有專門的「工具角色」，所以我們用一則 `user` 訊息，開頭加上 `[工具結果]` 標記，讓模型知道「這不是使用者說的話，是程式查到的資料」：

```text
  messages 的變化（一次完整的工具呼叫）：

  [system]     SYSTEM_PROMPT + TOOL_PROMPT
  [user]       星期五有什麼課？
                         ── 第 1 次呼叫 LLM ──
  [assistant]  {"tool": "get_schedule", "args": {"day": "星期五"}}      ← 模型的「紙條」
                         ── 程式執行 get_schedule(day="星期五") ──
  [user]       [工具結果] get_schedule({"day": "星期五"}) → {"day": "星期五", "courses": [...]}
                         ── 第 2 次呼叫 LLM ──
  [assistant]  {"answer": "你星期五早上 9:10 有程式設計實習。"}
```

注意：**一個問題呼叫了兩次 LLM。** 第一次讓它決定用什麼工具，第二次讓它根據結果回答。這也是第 3 章說的「對話記憶」的應用：第二次呼叫時，模型看得到自己第一次寫的紙條，也看得到工具結果。

執行工具的函式叫 `run_tool(name, args)`：

1. 用 `name` 從 `TOOLS` 找到函式。
2. 用 `args` 當參數執行。
3. 把結果轉成字串（模型只能讀文字）。

### 5.7 手刻版的限制

手刻版能動，但跑幾次之後就會發現不少問題：

| 限制 | 說明 | 哪一章解決 |
|------|------|-----------|
| 格式常出錯 | 模型可能漏了 `args`、拼錯工具名稱、加上多餘的文字 | 第 6 章：API 內建工具呼叫 |
| prompt 越寫越長 | 每多一個工具，`TOOL_PROMPT` 就要多寫一段說明和範例 | 第 6 章：用 JSON Schema 描述工具 |
| 一次只能用一個工具 | 「明天有什麼課？」需要先查時間、再查課表，兩步驟 | 第 7 章：Agent 迴圈 |
| 工具出錯整個程式當掉 | 例如 `get_schedule(day="明天")`、除以零 | 第 8 章：把錯誤回傳給模型 |
| 工具結果偽裝成使用者的話 | 用 `user` 角色送工具結果，模型分不太清楚誰是誰 | 第 6 章（專用格式）、第 9 章（安全） |

【動手做】的程式 5-5 會讓你親眼看到「一次只能用一個工具」的限制。

### 程式 5-0：準備環境（接續第 4 章）

如果你是接著第 4 章在同一個筆記本裡執行，而且執行階段沒有重新啟動過，可以跳過這一段。

```python
!pip install -q -U google-genai

import json
from google import genai
from google.genai import types
from google.colab import userdata

# ===== 開關：沒有 API key 就改成 True =====
USE_MOCK = False

# 全書使用的模型名稱
MODEL_NAME = "gemini-3.5-flash-lite"

# 有 API key 才建立連線物件
if not USE_MOCK:
    api_key = userdata.get("GEMINI_API_KEY")
    client = genai.Client(api_key=api_key)


def call_llm(messages, temperature=None, max_output_tokens=1024, json_mode=False):
    """
    把通用格式的 messages 送給 Gemini，回傳模型的文字回答。
    messages 的格式：[{"role": "system" / "user" / "assistant", "content": "文字"}, ...]
    json_mode=True 時，要求 Gemini 一定要輸出合法的 JSON。
    """
    system_text = None
    contents = []

    # 把通用格式轉成 Gemini 的格式
    for msg in messages:
        if msg["role"] == "system":
            system_text = msg["content"]
        else:
            role = "model" if msg["role"] == "assistant" else "user"
            contents.append({"role": role, "parts": [{"text": msg["content"]}]})

    response = client.models.generate_content(
        model=MODEL_NAME,
        contents=contents,
        config=types.GenerateContentConfig(
            system_instruction=system_text,
            temperature=temperature,
            max_output_tokens=max_output_tokens,
            response_mime_type="application/json" if json_mode else None,
        ),
    )

    return response.text or ""


# 校園小助理的角色與規則（全書共用）
SYSTEM_PROMPT = """你是「金門大學校園小助理」，服務對象是金門大學的學生。

規則：
1. 一律使用繁體中文回答。
2. 回答簡短，最多三句話。
3. 不知道或不確定的事情，直接說「我不確定」，絕對不要編造。
4. 只回答和校園生活、課業有關的問題；其他問題請禮貌地拒絕。"""

WEEKDAYS = ["星期一", "星期二", "星期三", "星期四", "星期五", "星期六", "星期日"]


def parse_json_reply(text):
    """
    把模型的回答解析成 dict。
    會先去掉 ```json 標記和前後多餘的文字；解析失敗就回傳 None。
    """
    start = text.find("{")
    end = text.rfind("}")
    if start == -1 or end == -1 or end < start:
        return None
    try:
        return json.loads(text[start:end + 1])
    except json.JSONDecodeError:
        return None


# 有 API key：llm 指向真的 Gemini；沒有的話，程式 5-6 會把 llm 設成 mock_llm
if not USE_MOCK:
    llm = call_llm

print("環境準備完成！USE_MOCK =", USE_MOCK)
```

**逐段解說：**

- 這段集合了第 2～4 章會用到的東西：`MODEL_NAME`、`client`、升級版 `call_llm()`、`SYSTEM_PROMPT`、`WEEKDAYS`、`parse_json_reply()`，內容都和前面章節相同。
- **和之前不同的地方**：`USE_MOCK` 開關移到最前面。`USE_MOCK = True` 時，**不會去讀 API key**，這樣沒有金鑰的讀者執行這段也不會出錯。
- 最後的 `if not USE_MOCK: llm = call_llm`：有金鑰的話先讓 `llm` 指向 `call_llm`。

**預期輸出：**

```text
環境準備完成！USE_MOCK = False
```

### 程式 5-1：準備四個工具

這段**不需要 API key**，因為工具就只是普通的 Python 函式。

```python
from datetime import datetime
from zoneinfo import ZoneInfo

# ===== 假的資料 =====
FAKE_SCHEDULE = {
    "星期一": [
        {"time": "08:10-10:00", "course": "計算機概論", "room": "理工大樓 E101"},
        {"time": "13:10-15:00", "course": "微積分", "room": "理工大樓 E203"},
    ],
    "星期二": [
        {"time": "10:10-12:00", "course": "程式設計", "room": "電腦教室 C301"},
    ],
    "星期三": [
        {"time": "10:10-12:00", "course": "資料結構", "room": "理工大樓 E105"},
        {"time": "15:10-17:00", "course": "大一英文", "room": "人文大樓 H201"},
    ],
    "星期四": [
        {"time": "08:10-10:00", "course": "離散數學", "room": "理工大樓 E203"},
    ],
    "星期五": [
        {"time": "09:10-12:00", "course": "程式設計實習", "room": "電腦教室 C302"},
    ],
    "星期六": [],
    "星期日": [],
}

FAKE_WEATHER = {
    "金門": {
        "今天": {"天氣": "多雲", "氣溫": "18-23°C", "降雨機率": "20%", "風力": "東北風 4 級"},
        "明天": {"天氣": "陣雨", "氣溫": "16-20°C", "降雨機率": "70%", "風力": "東北風 6 級"},
    },
    "台北": {
        "今天": {"天氣": "陰", "氣溫": "17-21°C", "降雨機率": "40%", "風力": "東北風 3 級"},
        "明天": {"天氣": "小雨", "氣溫": "15-19°C", "降雨機率": "80%", "風力": "東北風 4 級"},
    },
}


# ===== 四個工具 =====
def calculator(expression):
    """計算數學算式，例如 "(3 + 4) * 2"。只允許數字和 + - * / ( ) ."""
    allowed = set("0123456789+-*/(). ")
    # 檢查每個字元都在允許的範圍內
    if not set(expression) <= allowed:
        return "錯誤：算式只能包含數字和 + - * / ( ) ."
    # 不允許次方（**），避免算出天文數字讓程式卡住
    if "**" in expression:
        return "錯誤：不支援次方運算"
    # 不給 eval 任何內建函式，降低風險
    return eval(expression, {"__builtins__": {}}, {})


def get_current_time():
    """取得台灣現在的日期、星期與時間"""
    now = datetime.now(ZoneInfo("Asia/Taipei"))
    weekday = WEEKDAYS[now.weekday()]
    return f"{now.strftime('%Y-%m-%d')} {weekday} {now.strftime('%H:%M')}"


def get_schedule(day):
    """查詢某一天的課表，day 必須是「星期一」～「星期日」"""
    if day not in FAKE_SCHEDULE:
        raise ValueError(f"day 必須是星期一到星期日，收到的是：{day}")
    return {"day": day, "courses": FAKE_SCHEDULE[day]}


def get_weather(city):
    """查詢某個城市今天和明天的天氣"""
    if city not in FAKE_WEATHER:
        return {"city": city, "error": "沒有這個城市的天氣資料"}
    return {"city": city, **FAKE_WEATHER[city]}


# ===== 直接測試：工具就只是普通的函式 =====
print(calculator("(3 + 4) * 2"))
print(calculator("12345 * 6789"))
print(calculator("__import__('os')"))
print(get_current_time())
print(get_schedule("星期三"))
print(get_weather("金門"))
```

**逐段解說：**

- **`FAKE_SCHEDULE`**：用 dict 模擬課表。key 是星期幾，value 是那天的課程 list，每堂課又是一個 dict。星期六、日是空 list，代表沒課。
- **`FAKE_WEATHER`**：用巢狀 dict 模擬天氣，第一層是城市，第二層是「今天／明天」。
- **`calculator(expression)`**：
  - `set(expression) <= allowed`：`set()` 把字串拆成「不重複字元的集合」，`<=` 檢查它是不是 `allowed` 的子集合，也就是「每個字元都是允許的」。
  - `eval(expression, {"__builtins__": {}}, {})`：計算算式。第二個參數把 Python 內建函式全部拿掉，就算檢查有漏洞，能做的事也很有限。
- **`get_current_time()`**：
  - Colab 的雲端電腦用的是**世界標準時間（UTC）**，比台灣慢 8 小時。所以要用 `ZoneInfo("Asia/Taipei")` 指定台灣時區。
  - `now.weekday()` 回傳 0（星期一）到 6（星期日），剛好可以當 `WEEKDAYS` 的索引。這裡用到第 4 章的 `WEEKDAYS`。
  - `strftime('%Y-%m-%d')` 把時間格式化成「年-月-日」，`'%H:%M'` 是「時:分」。
- **`get_schedule(day)`**：如果 `day` 不是星期一～星期日，就 `raise ValueError` 丟出錯誤。這個錯誤在本章會讓程式當掉，第 8 章會教你怎麼處理。
- **`get_weather(city)`**：`{"city": city, **FAKE_WEATHER[city]}` 裡的 `**` 會把 dict 的內容「展開」放進新的 dict，結果是 `{"city": "金門", "今天": {...}, "明天": {...}}`。
- **工具回傳的型別不一樣**：有的是數字、有的是字串、有的是 dict。等一下的 `run_tool()` 會統一轉成字串。

### 程式 5-2：工具清單 `TOOLS` 與 `run_tool()`

這段也**不需要 API key**。

```python
# 工具清單：工具名稱（字串）→ 函式本身
TOOLS = {
    "calculator": calculator,
    "get_current_time": get_current_time,
    "get_schedule": get_schedule,
    "get_weather": get_weather,
}


def run_tool(name, args):
    """依照工具名稱找到函式並執行，把結果轉成字串回傳"""
    func = TOOLS[name]          # 用名稱找到函式
    result = func(**args)       # 把 args 這個 dict 展開成參數，執行函式
    # 模型只讀得懂文字，所以把結果轉成字串
    if isinstance(result, str):
        return result
    return json.dumps(result, ensure_ascii=False)


def tool_result_message(name, args, result):
    """把工具結果包成一則訊息，準備送回給模型"""
    args_text = json.dumps(args, ensure_ascii=False)
    return {"role": "user", "content": f"[工具結果] {name}({args_text}) → {result}"}


# 測試：模擬「模型說要用某個工具」
print(run_tool("get_schedule", {"day": "星期五"}))
print(run_tool("calculator", {"expression": "3 * (2 + 5)"}))
print(run_tool("get_current_time", {}))
print(tool_result_message("calculator", {"expression": "3 * (2 + 5)"}, "21"))
```

**逐段解說：**

- **`TOOLS`**：key 是字串，value 是函式本身（注意**沒有括號**）。
- **`run_tool(name, args)`**：
  - `TOOLS[name]`：用模型給的名稱找到函式。
  - `func(**args)`：`**` 用在呼叫函式時，會把 dict **展開成具名參數**。例如 `args = {"day": "星期五"}`，`func(**args)` 就等於 `func(day="星期五")`。`get_current_time` 不需要參數，`args` 是空 dict `{}`，展開後就是 `func()`。
  - `isinstance(result, str)`：檢查結果是不是字串。是的話直接回傳；不是的話（數字、dict）用 `json.dumps()` 轉成 JSON 字串。
- **`tool_result_message(name, args, result)`**：把結果包成 5.6 節說的格式：一則 `user` 訊息，開頭是 `[工具結果]`。包成函式是為了讓每次的格式都一模一樣，第 7 章也會繼續用它。

**預期輸出（時間依執行當下而定）：**

```text

21
2026-11-27 星期五 21:30
{'role': 'user', 'content': '[工具結果] calculator({"expression": "3 * (2 + 5)"}) → 21'}
```

到這裡，「動手的人」已經準備好了。接下來要教「下指令的人」怎麼寫紙條。

### 程式 5-4：完成一次完整的工具呼叫（一步一步來）

接在程式 5-3 後面執行，我們把 5.6 節的流程一步一步走完，每一步都印出來：

```python

**逐段解說：**

- **步驟 2**：從 dict 取出工具名稱和參數，交給 `run_tool()` 執行。`action.get("args", {})`：如果模型忘了寫 `args`，就用空 dict。**這一步是你的程式在執行，不是模型。**
- **步驟 3**：照 5.6 節的圖，先把模型的紙條以 `assistant` 身分加進去，再把工具結果用 `tool_result_message()` 加進去。現在 `messages` 有 4 則：system、使用者問題、紙條、工具結果。
- **步驟 4**：第二次呼叫 LLM。這次模型看得到工具結果，所以輸出 `{"answer": ...}`。

**預期輸出：**

這就是工具呼叫的完整流程！模型說出了**真實存在於你課表裡**的課程，而不是憑空編造。

    reply = llm(messages, temperature=0)

### 程式 5-6：升級 `mock_llm()`，讓假的 LLM 也會寫紙條

這段**不需要 API key**。第 4 章的 `mock_llm()` 只會輸出意圖 JSON，現在要讓它也會輸出 `{"tool": ...}` 和 `{"answer": ...}`。

```python
import re


def mock_next_action(question, used):
    """
    假的 LLM 的「大腦」：根據問題裡的關鍵字，決定下一步要用哪個工具。
    used：已經用過的工具 → 結果文字，例如 {"get_current_time": "2026-11-27 星期五 21:30"}
    """
    # 問題裡有沒有直接寫星期幾
    day = None
    for d in WEEKDAYS:
        if d in question:
            day = d
            break

    # 規則 1：需要知道現在時間（問時間，或問課表卻沒說星期幾）
    need_time = any(k in question for k in ["幾點", "幾號", "星期幾", "時間", "日期"])
    if "課" in question and day is None:
        need_time = True
    if need_time and "get_current_time" not in used:
        return {"tool": "get_current_time", "args": {}}

    # 規則 2：問課表
    if "課" in question and "get_schedule" not in used:
        if day is None:
            # 從時間結果找出「今天星期幾」，再推算明天
            time_text = used.get("get_current_time", "")
            for i, d in enumerate(WEEKDAYS):
                if d in time_text:
                    day = WEEKDAYS[(i + 1) % 7] if "明天" in question else d
                    break
        if day is not None:
            return {"tool": "get_schedule", "args": {"day": day}}

    # 規則 3：問天氣
    if any(k in question for k in ["天氣", "雨", "騎車", "傘"]) and "get_weather" not in used:
        city = "台北" if "台北" in question else "金門"
        return {"tool": "get_weather", "args": {"city": city}}

    # 規則 4：問題裡有算式（數字 + 運算符號 + 數字）
    question_math = question.replace("乘以", "*").replace("除以", "/").replace("加", "+").replace("減", "-")
    match = re.search(r"\d[\d\.\s\(\)]*[\+\-\*/][\d\.\s\+\-\*/\(\)]*\d", question_math)
    if match and "calculator" not in used:
        return {"tool": "calculator", "args": {"expression": match.group()}}

    # 規則 5：不需要（或不再需要）工具，直接回答
    if used:
        summary = "；".join(f"{name} → {result}" for name, result in used.items())
        return {"answer": f"（mock）根據查詢結果：{summary}"}
    return {"answer": "（mock）你好！我是假的校園小助理，只會用規則回答問題。"}


def mock_llm(messages, temperature=None, max_output_tokens=1024, json_mode=False):
    """
    假的 LLM：用簡單的關鍵字規則模擬回答。
    呼叫方式和 call_llm() 完全一樣，回傳的也是字串。
    """
    system_text = " ".join(m["content"] for m in messages if m["role"] == "system")

    # 找出使用者原本的問題：最後一則「不是工具結果」的 user 訊息
    question = ""
    question_index = 0
    for i in range(len(messages) - 1, -1, -1):
        msg = messages[i]
        if msg["role"] == "user" and not msg["content"].startswith("[工具結果]"):
            question = msg["content"]
            question_index = i
            break

    # 收集這個問題之後，已經拿到的工具結果
    used = {}
    for msg in messages[question_index + 1:]:
        if msg["role"] == "user" and msg["content"].startswith("[工具結果]"):
            body = msg["content"][len("[工具結果] "):]
            name = body.split("(")[0]
            result = body.split(" → ", 1)[1] if " → " in body else ""
            used[name] = result

    # ===== 情況一：system prompt 有工具說明（第 5 章起） =====
    if '"tool"' in system_text:
        result = mock_next_action(question, used)
    # ===== 情況二：要求意圖 JSON（第 4 章） =====
    elif json_mode or "JSON" in system_text:
        day = None
        for d in WEEKDAYS:
            if d in question:
                day = d
                break
        if "課" in question:
            result = {"intent": "schedule", "day": day, "reply": "我幫你查課表。"}
        elif "天氣" in question or "雨" in question:
            result = {"intent": "weather", "day": day, "reply": "我幫你查天氣。"}
        else:
            result = {"intent": "chat", "day": day, "reply": "（mock）你好，我是假的小助理！"}
    # ===== 情況三：一般文字回答 =====
    else:
        if "你好" in question or "你是誰" in question:
            return "（mock）你好！我是假的校園小助理，只會用規則回答問題。"
        return f"（mock）我收到你的訊息了：「{question}」"

    text = json.dumps(result, ensure_ascii=False)
    # 模擬真實模型的壞習慣：沒開 JSON 模式時，用 ```json 把答案包起來
    if not json_mode:
        text = "```json\n" + text + "\n```"
    return text

print("第 2 次：", mock_llm(test_messages))
print("目前 llm 指向：", llm.__name__)
```

> 注意：這段程式用到程式 5-3 的 `TOOL_PROMPT` 和程式 5-2 的 `tool_result_message()`。沒有 API key 的讀者如果先跑這段，請先執行程式 5-1、5-2，再把程式 5-3 開頭的 `TOOL_PROMPT = """..."""` 那一段執行一次。

**逐段解說：**

- **`mock_next_action(question, used)`**：假 LLM 的「大腦」，照順序檢查五條規則，**第一條符合的就回傳**：
  - **規則 1**：問題需要知道時間（直接問「幾點」「幾號」「星期幾」，或問課表卻沒說星期幾），而且還沒查過時間 → 用 `get_current_time`。
  - **規則 2**：問課表，而且還沒查過 → 用 `get_schedule`。如果問題沒寫星期幾，就從時間結果裡找出「今天星期幾」，用 `WEEKDAYS` 的索引算出明天：`(i + 1) % 7` 的 `% 7` 讓星期日（索引 6）的明天回到星期一（索引 0）。
  - **規則 3**：問天氣 → 用 `get_weather`。
  - **規則 4**：先把「乘以」「除以」等中文換成符號，再用**正規表示式**（regular expression，一種描述文字樣式的語法，Python 用 `re` 模組）找出「數字、運算符號、數字」這樣的片段 → 用 `calculator`。
  - **規則 5**：工具都用完了，把所有結果串起來當作回答；完全沒用過工具就打招呼。
  - `used` 記錄「已經用過哪些工具」，所以同一個工具不會重複用，也讓 mock 可以一步一步往下走。這個設計在第 7 章的 Agent 迴圈裡會派上用場。
- **`mock_llm()`**：
  - **找原本的問題**：從最後面往前找，第一則「`user` 而且不是 `[工具結果]` 開頭」的訊息。`range(len(messages) - 1, -1, -1)` 是從最後一個索引倒數到 0。
  - **收集工具結果**：在原本問題之後的 `[工具結果]` 訊息，用字串切割取出工具名稱（`(` 前面）和結果（` → ` 後面）。
  - **情況一**：system prompt 裡有 `"tool"` 這個字（代表有 `TOOL_PROMPT`），交給 `mock_next_action()`。
  - **情況二、三**：和第 4 章的 `mock_llm()` 相同，保留第 4 章的功能。
  - 最後一樣故意用 `` ```json `` 包起來，考驗 `parse_json_reply()`。
- **`llm = mock_llm if USE_MOCK else call_llm`**：重新設定開關。

## 【常見錯誤】

| 錯誤情況 | 原因 | 解決方式 |
|---------|------|---------|
| 以為模型「執行」了工具 | 誤解工具呼叫的本質 | 模型只輸出 JSON 紙條；執行的永遠是你的 `run_tool()` |
| `KeyError: 'get_scheduel'` | 模型拼錯工具名稱，`TOOLS` 裡找不到 | 本章先注意 prompt 寫清楚；第 8 章會把錯誤回傳給模型讓它修正 |
| `TypeError: get_schedule() got an unexpected keyword argument 'date'` | 模型寫錯參數名稱（`date` 而不是 `day`） | 同上；第 6 章的 JSON Schema 會讓這種錯誤大幅減少 |
| `ValueError: day 必須是星期一到星期日` | 模型直接傳 `"明天"` 給 `get_schedule` | 在 prompt 中要求先用 `get_current_time`；第 8 章處理例外 |
| `KeyError: 'tool'` | 模型回了 `{"answer": ...}` 以外的奇怪格式 | 先檢查 `"answer" in action`，再取 `action["tool"]` |
| 工具結果加進去了，模型卻好像沒看到 | 忘了把模型的紙條（assistant）也加進 messages，對話順序不完整 | 每次都要依序加入：assistant 紙條 → `[工具結果]` |
| 時間差了 8 小時 | Colab 使用 UTC 時區 | `datetime.now(ZoneInfo("Asia/Taipei"))` |
| 直接 `eval(模型給的字串)` | 模型給的參數可能有惡意程式碼 | 先檢查內容，並限制 `eval` 能用的功能（參考 `calculator`） |

## 【本章小結】

1. **LLM 自己不會執行任何東西**：它只會輸出「要用哪個工具、參數是什麼」的紙條，真正執行的是你的程式。
2. 工具就是普通的 Python 函式；用 `TOOLS` 這個 dict 把「工具名稱字串」對應到「函式本身」，再用 `run_tool(name, args)` 執行。
3. 手刻版完全靠 prompt：`TOOL_PROMPT` 說明工具清單與輸出格式，模型輸出 `{"tool": ..., "args": ...}` 或 `{"answer": ...}`。
4. 一次完整的工具呼叫要呼叫兩次 LLM：第一次決定用什麼工具，程式執行後把結果加進 messages，第二次根據結果回答。
5. 手刻版的限制：格式容易錯、prompt 越來越長、一次只能用一個工具、工具出錯就當掉。接下來的三章會一一解決。
