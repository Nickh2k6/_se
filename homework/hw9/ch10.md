# 第 10 章　記憶與知識（進階）

## 【本章重點】

Agent 需要兩種「記得」：**記得你**（記憶）和**知道它原本不知道的事**（知識）。
**記憶**分成兩種：**短期記憶**是這次對話的內容（第 3 章的 `chat_history`），**長期記憶**是存在檔案裡、下次打開還在的重要資訊。兩者最後都只是**放進 messages 裡的文字**。
**知識**用 **RAG（檢索增強生成）** 補上：先從資料裡**搜尋**出相關段落，再**放進 prompt**，讓模型照著資料回答，而不是憑記憶接龍。本章用最簡單的關鍵字搜尋示範，並看看它的極限在哪裡。

---

## 【為什麼需要這一章】

到第 9 章為止，校園小助理已經很能幹了，但還有兩個明顯的問題：

**問題一：它不記得你。**

```text
你：我叫小明，是資工系一年級的學生。
小助理：你好小明！
（下一次呼叫 run_agent）
你：我叫什麼名字？
小助理：抱歉，我不知道你的名字。
```

第 7～9 章的 `run_agent()` 每次都從一個全新的 `messages` 開始，**連上一句話都不記得**，更別說關掉 Colab 再打開了。

**問題二：它不知道學校的規定。**

```text
你：退選的期限是什麼時候？
小助理：一般大學的退選期限通常在……（開始接龍、編造）
```

學校的規定不在模型的訓練資料裡（第 1 章），而且每間學校都不一樣。`SYSTEM_PROMPT` 的規則 3 會讓它說「我不確定」，但這樣也沒幫上忙。

這一章要解決的問題是：**怎麼讓 Agent 記得使用者，並且能查詢它原本不知道的資料？**

## 【觀念解說】

### 10.1 記憶和知識，其實都是「放進 messages 的文字」

先記住一個最重要的觀念，它來自第 3 章：

> **模型只看得到「這一次送過去的 messages」。**

所以不管是「記得你叫小明」還是「知道退選期限」，做法都一樣：**在呼叫模型之前，把相關的文字放進 messages。** 差別只在這些文字從哪裡來：

```text
                         ┌──────────── messages ────────────┐
  SYSTEM_PROMPT ────────▶│ [system] 角色規則 ＋ Agent 守則    │
  長期記憶（檔案） ──────▶│          ＋ 「你記得：小明、資工系」│  ← 10.3 節
                         │                                   │
  短期記憶（history）───▶│ [user] 我叫小明                    │  ← 10.2 節
                         │ [assistant] 你好小明！             │
                         │                                   │
  使用者這次的問題 ─────▶│ [user] 退選期限是什麼時候？         │
                         │                                   │
  搜尋到的資料（RAG）───▶│ [tool] search_notes → 加退選規定…  │  ← 10.4～10.6 節
                         └───────────────────────────────────┘
```

### 10.2 短期記憶 vs 長期記憶

**比喻：上課做筆記。**

- **短期記憶**像是你**這堂課**的印象：老師剛剛講了什麼，你都還記得。但下課過了一週，細節就忘光了。
- **長期記憶**像是你**寫在筆記本上**的重點：只記重要的，但隨時翻得到，下學期也還在。

| | 短期記憶 | 長期記憶 |
|---|---|---|
| 是什麼 | 這次對話的內容 | 跨對話保存的重要資訊 |
| 存在哪裡 | 程式裡的 list（`history`） | 檔案（本章用 JSON 檔） |
| 關掉 Colab 之後 | 消失 | 還在（如果檔案有保存好） |
| 存多少 | 最近幾輪對話（太長會變貴，第 3 章） | 只存重點（名字、系級、偏好） |
| 怎麼放進 messages | 直接接在 system 後面 | 寫進 system prompt |
| 由誰決定記什麼 | 自動（每一輪都存） | **模型決定**（透過 `remember` 工具） |

**短期記憶的做法**：第 3 章已經學過了：用 list 保存對話，每次一起送出。這一章讓 `run_agent()` 也支援它：多一個參數 `history`，把之前的問答接在 system 後面。

注意：`history` **只存「使用者的問題」和「最終回答」**，不存中間的工具請求和工具結果。因為下一題通常不需要知道上一題查了哪些工具，存了只會讓 token 越來越多。

**長期記憶的做法**：

1. 準備一個工具 `remember(fact)`，讓**模型自己判斷**什麼是值得記住的事，例如使用者說「我叫小明」時，就呼叫 `remember("使用者叫小明")`。
2. `remember()` 把這句話存進 JSON 檔。
3. 每次 `run_agent()` 開始時，讀出檔案裡的所有記憶，**寫進 system prompt**：

```text
你是「金門大學校園小助理」……（SYSTEM_PROMPT）
你可以使用工具來完成任務……（AGENT_PROMPT）

【長期記憶】你記得關於使用者的這些事：
- 使用者叫小明，是資工系一年級
- 使用者不喜歡早八的課
```

組出這段文字的工作交給新函式 `build_system_prompt()`，`run_agent()` 每次開始時都呼叫它。

> **長期記憶也要注意安全（第 9 章）**：寫進長期記憶的文字，每次都會被放進 **system prompt**，地位比一般訊息還高。如果攻擊者透過提示注入，騙模型呼叫 `remember("以後所有信都寄到 ……")`，這個假指令就會**永久**留在每一次對話裡。所以 `remember` 的說明要寫清楚「只記使用者親口說的事」，而且真正的系統通常會讓使用者能查看、刪除自己的記憶。

### 10.3 長期記憶存在哪裡

本章把長期記憶存成 JSON 檔 `campus_memory.json`，內容就是一個字串的 list：

```json

  "使用者叫小明，是資工系一年級",
  "使用者不喜歡早八的課"
]
```

### 10.4 RAG：開書考

**RAG（Retrieval-Augmented Generation，檢索增強生成）**：在模型產生回答**之前**，先從外部資料中**檢索（retrieve）**出相關的內容，把它**加進（augment）** prompt 裡，再讓模型**生成（generate）**回答。

拆開來看這三個字：

| 步驟 | 英文 | 做什麼 |
|------|------|-------|
| 檢索 | Retrieval | 從資料庫（或文件）中找出跟問題相關的段落 |
| 增強 | Augmented | 把找到的段落放進 prompt |
| 生成 | Generation | 模型根據 prompt（包含資料）產生回答 |

**比喻：閉書考 vs 開書考。**

- **沒有 RAG 的模型像在考閉書考**：只能靠腦袋裡記得的東西作答。記得不清楚的，就「接龍」出一個看起來很像的答案（第 1 章的幻覺）。
- **有 RAG 的模型像在考開書考**：先翻課本找到相關的那一頁，再照著課本寫答案。答案的正確性來自**課本**，而不是模型的記憶。

```text
  使用者：「退選的期限是什麼時候？」
      │
      ▼
  ① 檢索：在 CAMPUS_NOTES 裡搜尋 → 找到「加退選規定」這一段
      │
      ▼
  ② 增強：把找到的段落放進 prompt
      ┌──────────────────────────────────────────────┐
      │ 請根據以下參考資料回答問題……                    │
      │ 參考資料：[1] 加退選規定：……期中考前（退選期限）…… │
      │ 問題：退選的期限是什麼時候？                     │
      └──────────────────────────────────────────────┘
      │
      ▼
  ③ 生成：模型照著資料回答 →「退選期限是期中考前，要填停修申請單……」
```

**RAG 和工具呼叫是什麼關係？** 其實 RAG 的「檢索」就是一種工具！本章的做法是：

1. 先寫一個搜尋函式 `search_notes(query)`，親手做一次 RAG，看看 prompt 長什麼樣子（程式 10-4）。
2. 再把它變成 Agent 的工具，讓模型**自己決定**什麼時候要查資料、要查什麼關鍵字（程式 10-5）。

### 10.5 用關鍵字搜尋做最簡單的 RAG

搜尋的方法有很多種，本章用最簡單、最容易看懂的：**關鍵字比對**。

英文的單字之間有空格，很容易切出「關鍵字」。但中文沒有空格，「退選的期限是什麼時候」要怎麼切？本章用一個簡單的方法：**兩個字一組**。

**Bigram（二元組）**：把文字切成「每兩個相鄰的字一組」的片段。例如：

```text
  「退選期限」 → 退選、選期、期限
```

搜尋時，計算「問題的每一組，在資料裡出現了幾組」，出現越多組，分數越高：

```text
  問題：「退選的期限是什麼時候？」
  切成兩字一組（跳過含有「的、是、什、麼」等常見字或標點的組合）：
        退選、期限、時候

  資料                  有出現的組合            分數
  ─────────────────────────────────────────────────
  加退選規定            退選、期限              2   ← 最高分，就是它
  請假規定              （沒有）                0
  圖書館借閱規定         （沒有）                0
  ……
```

為什麼要跳過「的、是、什麼」這些字？因為它們到處都有，留著的話，幾乎每段資料都會「命中」，分數就沒有意義了。這些字在搜尋領域叫做**停用詞（stop words）**。

### 10.6 把搜尋包成工具

把 `search_notes()` 加進 `TOOLS` 和 `TOOL_DECLARATIONS`，模型就能自己決定：

- 問到學校規定 → 先 `search_notes`，再照著結果回答。
- 問到課表、天氣 → 用原本的工具。
- 搜尋不到 → 照 `SYSTEM_PROMPT` 規則 3，說「我不確定」。

工具說明（`description`）要寫清楚：「回答學校規定相關的問題前，一定要先搜尋，並且**根據搜尋結果**回答」。

### 10.7 關鍵字搜尋的限制

關鍵字搜尋簡單好懂，但它只看「**字有沒有一樣**」，不懂「**意思是不是一樣**」：

| 問題 | 應該找到 | 關鍵字搜尋的結果 | 原因 |
|------|---------|----------------|------|
| 放棄一門課要怎麼辦？ | 加退選規定 | ❌ 找不到 | 資料寫的是「退選」「停修」，不是「放棄」 |
| 書可以借多久？ | 圖書館借閱規定 | ❌ 找不到 | 資料寫的是「借期」，切出來的「借多」「多久」都對不上 |
| 生病不能上課怎麼辦？ | 請假規定 | ❌ 找錯（加退選規定） | 剛好都有「不能」兩個字 |

真正的 RAG 系統通常會用**向量搜尋（vector search）**：

**嵌入（embedding）**：用一個專門的模型，把一段文字轉換成一串數字（叫做**向量，vector**）。**意思相近的文字，轉出來的數字也會很接近**。

```text
  「放棄一門課」 → [0.12, -0.53, 0.88, ……]  ┐
                                              ├─ 數字很接近 → 意思很像！
  「退選課程」   → [0.10, -0.49, 0.91, ……]  ┘

  「今天天氣好」 → [-0.77, 0.31, 0.05, ……]  ← 數字差很多 → 意思不同
```

搜尋時，把問題也轉成向量，找出「數字最接近」的資料段落。這樣就算用詞完全不同，只要**意思相近**就找得到。Gemini API 也有提供 embedding 模型，有興趣的話可以在官方文件搜尋「Embeddings」。

**但 RAG 的整體架構完全不變**：檢索 → 放進 prompt → 生成。換掉的只是「檢索」這一步的方法。你在本章學到的架構，到了真正的系統裡一樣適用。

```python
def calculator(expression):
    """計算數學算式，例如 "(3 + 4) * 2"。只允許數字和 + - * / ( ) ."""
    allowed = set("0123456789+-*/(). ")
    if not set(expression) <= allowed:
        return "錯誤：算式只能包含數字和 + - * / ( ) ."
    if "**" in expression:
        return "錯誤：不支援次方運算"
    return eval(expression, {"__builtins__": {}}, {})

    return f"{now.strftime('%Y-%m-%d')} {weekday} {now.strftime('%H:%M')}"

def call_llm_tools(messages, temperature=None, max_output_tokens=1024):
    """
    原生工具呼叫版的 call_llm：把通用格式的 messages 連同工具宣告一起送給 Gemini。
    回傳 dict：{"text": ..., "tool_calls": [...], "raw": ..., "usage": {"input": 輸入 token, "output": 輸出 token}}
    """
    system_text = None
    contents = []

    for msg in messages:
        if msg["role"] == "system":
            system_text = msg["content"]

        elif msg["role"] == "user":
            contents.append(types.Content(role="user", parts=[types.Part.from_text(text=msg["content"])]))

        elif msg["role"] == "assistant":
            if msg.get("raw") is not None:
                contents.append(msg["raw"])
            else:
                parts = []
                if msg.get("content"):
                    parts.append(types.Part.from_text(text=msg["content"]))
                for call in msg.get("tool_calls", []):
                    parts.append(types.Part(function_call=types.FunctionCall(name=call["name"], args=call["args"])))
                contents.append(types.Content(role="model", parts=parts))

        elif msg["role"] == "tool":
            part = types.Part.from_function_response(name=msg["name"], response={"result": msg["content"]})
            last = contents[-1] if contents else None
            if last is not None and last.role == "user" and last.parts[0].function_response is not None:
                last.parts.append(part)
            else:
                contents.append(types.Content(role="user", parts=[part]))

    response = client.models.generate_content(
        model=MODEL_NAME,
        contents=contents,
        config=types.GenerateContentConfig(
            system_instruction=system_text,
            temperature=temperature,
            max_output_tokens=max_output_tokens,
            tools=[types.Tool(function_declarations=TOOL_DECLARATIONS)],
        ),
    )

    content = response.candidates[0].content
    text = ""
    tool_calls = []
    if content is not None and content.parts:
        for part in content.parts:
            if part.function_call is not None:
                tool_calls.append({"name": part.function_call.name, "args": dict(part.function_call.args or {})})
            elif part.text and not part.thought:
                text += part.text

    # ===== 新增：整理 token 用量（欄位可能是 None，所以用 or 0） =====
    meta = response.usage_metadata
    usage = {
        "input": (meta.prompt_token_count or 0) if meta else 0,
        "output": ((meta.candidates_token_count or 0) + (meta.thoughts_token_count or 0)) if meta else 0,
    }

    return {"text": text, "tool_calls": tool_calls, "raw": content, "usage": usage}

def run_agent(user_input, max_steps=10, max_failures=3, token_budget=20000):

    可靠版 Agent 主迴圈。
    停止條件：① 模型給出最終回答 ② 超過 max_steps 步
             ③ 工具連續失敗 max_failures 次 ④ 累積 token 超過 token_budget
    """

        {"role": "system", "content": SYSTEM_PROMPT + "\n\n" + AGENT_PROMPT},
        {"role": "user", "content": user_input},
    ]
    AGENT_LOG.clear()            # 每次執行都從空的紀錄開始
    log_event(0, "start", question=user_input)

    total_tokens = 0             # 累積的 token 數
    failures = 0                 # 工具「連續」失敗的次數
    step = 0

    while step < max_steps:
        step += 1

        # ① 思考
        response = llm_tools(messages, temperature=0)
        step_tokens = response["usage"]["input"] + response["usage"]["output"]
        total_tokens += step_tokens
        log_event(step, "llm", tokens=step_tokens, total_tokens=total_tokens)

        # 停止條件 ①：正常結束
        if not response["tool_calls"]:
            print(f"[第 {step} 步] 最終回答：{response['text'].strip()}")
            print(f"[統計] 共 {step} 步，累積 {total_tokens} token")
            log_event(step, "answer", text=response["text"])
            return response["text"]

        # 停止條件 ④：超過 token 預算（在執行工具之前檢查）
        if total_tokens > token_budget:
            print(f"[停止] 累積 {total_tokens} token，超過預算 {token_budget}。")
            log_event(step, "stop", reason="token_budget")
            return "（抱歉，這個問題需要的資源超過上限，我先停下來了。）"

        if response["text"].strip():
            print(f"[第 {step} 步] 思考：{response['text'].strip()}")
        else:
            print(f"[第 {step} 步]")

        messages.append({
            "role": "assistant",
            "content": response["text"],
            "tool_calls": response["tool_calls"],
            "raw": response["raw"],
        })

        # ② 行動 ＋ ③ 觀察
        for call in response["tool_calls"]:
            print(f"          行動：{format_call(call['name'], call['args'])}")
            result = run_tool(call["name"], call["args"])
            print(f"          觀察：{result}")
            messages.append({"role": "tool", "name": call["name"], "content": result})

            # 計算連續失敗次數：失敗就加 1，成功就歸零
            ok = not result.startswith("錯誤：")
            failures = 0 if ok else failures + 1
            log_event(step, "tool", name=call["name"], args=call["args"], ok=ok, result=result[:100])

        # 停止條件 ③：工具連續失敗太多次
        if failures >= max_failures:
            print(f"[停止] 工具已經連續失敗 {failures} 次。")
            log_event(step, "stop", reason="too_many_failures")
            return "（抱歉，工具一直發生錯誤，請稍後再試。）"

    # 停止條件 ②：超過最大步數
    print(f"[停止] 已經跑了 {max_steps} 步，還沒有得到最終回答。")
    log_event(step, "stop", reason="max_steps")
    return "（抱歉，這個問題太複雜了，我沒辦法在限定的步數內完成。）"
```

```python
    messages = [{"role": "system", "content": build_system_prompt()}]

        messages.extend(history)
    messages.append({"role": "user", "content": user_input})

    AGENT_LOG.clear()
    log_event(0, "start", question=user_input)

    failures = 0

            print(f"[統計] 共 {step} 步，累積 {total_tokens} token")
            log_event(step, "answer", text=response["text"])
            # ===== 第 10 章新增：把這一輪的問答存進短期記憶 =====
            if history is not None:
                history.append({"role": "user", "content": user_input})
                history.append({"role": "assistant", "content": response["text"]})
            return response["text"]

        if total_tokens > token_budget:
            print(f"[停止] 累積 {total_tokens} token，超過預算 {token_budget}。")
            log_event(step, "stop", reason="token_budget")
            return "（抱歉，這個問題需要的資源超過上限，我先停下來了。）"

        if response["text"].strip():
            print(f"[第 {step} 步] 思考：{response['text'].strip()}")
        else:
            print(f"[第 {step} 步]")

        messages.append({
            "role": "assistant",
            "content": response["text"],
            "tool_calls": response["tool_calls"],
            "raw": response["raw"],
        })

        for call in response["tool_calls"]:
            print(f"          行動：{format_call(call['name'], call['args'])}")
            result = run_tool(call["name"], call["args"])
            print(f"          觀察：{result}")
            messages.append({"role": "tool", "name": call["name"], "content": result})

            ok = not result.startswith("錯誤：")
            failures = 0 if ok else failures + 1
            log_event(step, "tool", name=call["name"], args=call["args"], ok=ok, result=result[:100])

        if failures >= max_failures:
            print(f"[停止] 工具已經連續失敗 {failures} 次。")
            log_event(step, "stop", reason="too_many_failures")
            return "（抱歉，工具一直發生錯誤，請稍後再試。）"

    print(f"[停止] 已經跑了 {max_steps} 步，還沒有得到最終回答。")
    log_event(step, "stop", reason="max_steps")
    return "（抱歉，這個問題太複雜了，我沒辦法在限定的步數內完成。）"


# 測試：兩次呼叫共用同一個 history
history = []
run_agent("我叫小明，是資工系一年級的學生。", history=history)
print()
run_agent("我叫什麼名字？讀哪一系？", history=history)
print("\nhistory 現在有", len(history), "則訊息")
```

**逐段解說：**

- **`build_system_prompt()`**：目前只是把 `SYSTEM_PROMPT` 和 `AGENT_PROMPT` 接起來，跟之前一樣。把它獨立成函式，是為了讓程式 10-3 可以加上長期記憶，**而不用再改 `run_agent()`**。
- **新參數 `history=None`**：放在最後面、有預設值，所以 `run_agent("問題")` 這種舊寫法照樣能用。
- **建立 messages**：
  - 先放 system（由 `build_system_prompt()` 組出）。
  - `if history:` 有之前的對話，就用 `.extend()` 把它們全部接上。`.extend()` 是把另一個 list 的元素一個一個加進來（`.append()` 則是把整個 list 當成一個元素加進來）。
  - 最後才放這次的問題。
- **存進 history**：只有在**正常回答**時，才把「這次的問題」和「最終回答」加進 `history`。中間的工具請求和結果都不存（10.2 節說明了原因）。
  - `if history is not None`：使用者有傳 `history` 進來才存。注意這裡用 `is not None`，而不是 `if history:`，因為**空的 list `[]` 在 `if` 判斷裡會被當成「假」**，第一次呼叫時就不會存了。
- **測試**：兩次呼叫都傳入**同一個** `history` list。第一次結束後，`history` 裡有 2 則；第二次呼叫時，這 2 則會被送出去。

**預期輸出（真的模型）：**

```text
[第 1 步] 最終回答：你好小明！歡迎你，有任何校園或課業的問題都可以問我。
[統計] 共 1 步，累積 1187 token

[第 1 步] 最終回答：你叫小明，是資工系一年級的學生。
[統計] 共 1 步，累積 1236 token

history 現在有 4 則訊息
```

和程式 10-1 比較：這次 Agent 記得了，因為第二次呼叫的 messages 裡有第一次的問答。

> **用 mock 執行的讀者**：兩題都會得到 mock 的打招呼回答（mock 看不懂對話內容），但最後一行一樣是「history 現在有 4 則訊息」，可以確認問答有被存起來。

### 程式 10-3：長期記憶 —— 存進檔案、寫進 system prompt

```python
MEMORY_FILE = "campus_memory.json"


def load_memory():
    """從檔案讀出長期記憶（字串的 list）；檔案不存在就回傳空 list"""
    try:
        with open(MEMORY_FILE, encoding="utf-8") as f:

    except FileNotFoundError:

    """把長期記憶寫進檔案"""
    with open(MEMORY_FILE, "w", encoding="utf-8") as f:

        memory.append(fact)
        save_memory(memory)
```

### 程式 10-4：親手做一次 RAG —— 搜尋、放進 prompt

這段**不需要 API key**。

```python
# ===== 假的學校規定（以下內容皆為虛構範例，實際請以學校公告為準） =====
CAMPUS_NOTES = [
    {"title": "加退選規定", "content": "每學期開學後第一、二週為加退選期間，可在校務系統自行加選或退選。第三週起不能再加選；若要退選，須在期中考前（退選期限）填寫停修申請單，經導師與系主任簽名後送教務處。"},
    {"title": "請假規定", "content": "因病請假須附就醫證明，並在請假日起一週內於校務系統提出申請；事假須事先申請，並經任課老師同意。"},
    {"title": "圖書館借閱規定", "content": "大學部學生每人最多借閱圖書 20 冊，借期 30 天，可續借一次；逾期每冊每日罰款 5 元。"},
    {"title": "宿舍規定", "content": "新生宿舍於錄取後統一分配，舊生須在每年 5 月於學務處網站登記抽籤。宿舍內禁止使用電磁爐、電暖器等高耗電電器。"},
    {"title": "獎學金申請", "content": "前一學期學業平均 85 分以上、操行 80 分以上的學生，可在開學後一個月內向系辦申請成績優秀獎學金。"},
]

# 停用詞：到處都會出現、對搜尋沒有幫助的字和標點
STOP_CHARS = set("的了嗎呢吧啊是在有和與我你他她它們這那什麼怎要可，。？！?!、：:「」（）() ")


def make_bigrams(text):
    """把文字切成「兩個字一組」的片段，跳過含有停用詞的組合"""
    bigrams = set()
    for i in range(len(text) - 1):
        pair = text[i:i + 2]
        if not (set(pair) & STOP_CHARS):
            bigrams.add(pair)
    return bigrams


def search_notes(query, top_k=2):
    """用關鍵字（兩字一組）搜尋學校規定，回傳分數最高的 top_k 筆"""
    query_bigrams = make_bigrams(query)

    # 幫每一筆資料打分數：問題的兩字組，有幾組出現在這筆資料裡
    scored = []
    for note in CAMPUS_NOTES:
        text = note["title"] + note["content"]
        score = sum(1 for b in query_bigrams if b in text)
        if score > 0:
            scored.append((score, note))

    # 分數由高到低排序，取前 top_k 筆
    scored.sort(key=lambda item: item[0], reverse=True)
    results = [{"title": n["title"], "content": n["content"], "score": s} for s, n in scored[:top_k]]

    if not results:
        return {"query": query, "results": [], "message": "找不到相關的資料"}
    return {"query": query, "results": results}


def build_rag_prompt(question):
    """RAG 的「檢索 ＋ 增強」：搜尋相關資料，組成要送給模型的 prompt"""
    found = search_notes(question)
    refs = "\n".join(f"[{i + 1}] {r['title']}：{r['content']}" for i, r in enumerate(found["results"]))
    return (
        "請根據以下參考資料回答問題；參考資料裡沒有的，就說你不確定。\n\n"
        f"參考資料：\n{refs if refs else '（沒有找到相關資料）'}\n\n"
        f"問題：{question}"
    )


# ===== 測試 =====
question = "退選的期限是什麼時候？"
print("切成兩字一組：", sorted(make_bigrams(question)))
print("搜尋結果：", [(r["title"], r["score"]) for r in search_notes(question)["results"]])
print("\n===== 要送給模型的 prompt =====")
print(build_rag_prompt(question))
```

**逐段解說：**

- **`CAMPUS_NOTES`**：五筆虛構的學校規定，每筆有 `title`（標題）和 `content`（內容）。真實的系統裡，這些資料可能來自學校網站、PDF 文件或資料庫。
- **`STOP_CHARS`**：10.5 節說的停用詞，用 `set()` 把字串拆成字元的集合。
- **`make_bigrams(text)`**：
  - `for i in range(len(text) - 1)`：從第 0 個字走到倒數第 2 個字，每次取 `text[i:i + 2]`（相鄰兩個字）。
  - `set(pair) & STOP_CHARS`：`&` 是**集合的交集**，取出「兩邊都有的元素」。如果交集不是空的，代表這組含有停用詞，就跳過。
  - 用 `set` 存結果，重複的組合只會留一個。
- **`search_notes(query, top_k=2)`**：
  - `sum(1 for b in query_bigrams if b in text)`：數一數問題的兩字組，有幾組出現在這筆資料的標題或內容裡。
  - `scored.sort(key=lambda item: item[0], reverse=True)`：依照分數由大到小排序。**`lambda`** 是「一行的小函式」，`lambda item: item[0]` 的意思是「給我 item，我回傳 item 的第 0 個元素（分數）」，`sort` 就用它來比大小。
  - `scored[:top_k]`：只取前幾名。找不到就回傳 `message`，讓模型知道「沒有資料」，而不是讓它以為資料是空的就自己亂編。
- **`build_rag_prompt(question)`**：RAG 的前兩步。搜尋 → 把結果編號、條列 → 和問題一起組成 prompt。開頭要求模型「根據參考資料回答；沒有的就說不確定」，這是減少幻覺的關鍵。

**預期輸出：**

```text
切成兩字一組： ['時候', '期限', '退選']
搜尋結果： [('加退選規定', 2)]

===== 要送給模型的 prompt =====
請根據以下參考資料回答問題；參考資料裡沒有的，就說你不確定。

參考資料：
[1] 加退選規定：每學期開學後第一、二週為加退選期間，可在校務系統自行加選或退選。第三週起不能再加選；若要退選，須在期中考前（退選期限）填寫停修申請單，經導師與系主任簽名後送教務處。

問題：退選的期限是什麼時候？
```

這就是 RAG 送給模型的內容。模型只要「讀懂這段資料」就能回答，不需要事先知道學校的規定。

### 程式 10-5：把搜尋變成 Agent 的工具

### 程式 10-6：完整的聊天迴圈 —— 短期 ＋ 長期記憶

把第 3 章的聊天迴圈，和這一章的記憶結合起來：

```python
def chat_agent():
    """校園小助理聊天版：短期記憶 ＋ 長期記憶 ＋ 所有工具。輸入 exit 結束。"""
    history = []
    print("校園小助理：你好！有什麼可以幫你的嗎？（輸入 exit 結束）")

    while True:
        user_input = input("你：").strip()
        if user_input.lower() == "exit":
            print("校園小助理：掰掰！")
            break
        if user_input == "":
            continue

        run_agent(user_input, history=history)

        # 短期記憶只保留最近 10 則（5 輪問答）；重要的事已經存在長期記憶裡
        history[:] = trim_history(history, max_messages=10)

    return history


history = chat_agent()
```

**逐段解說：**

- **整體結構**和第 3 章程式 3-3 的 `chat()` 幾乎一樣：`while True` ＋ `input()` ＋ 輸入 `exit` 結束。差別是每一輪呼叫的是 `run_agent()`（有工具、有記憶的 Agent），而不是單純的 `call_llm()`。
- **短期記憶**：`history` 傳給 `run_agent()`，每一輪正常回答後會自動加入問答。
- **`history[:] = trim_history(...)`**：
  - 用第 3 章的 `trim_history()` 只保留最近 10 則，避免對話越長越貴。
  - 寫成 `history[:] =`（**切片賦值**），而不是 `history =`，代表「把 `history` 這個 list **裡面的內容**換掉」，而不是讓 `history` 這個名字指向一個新的 list。這樣做比較保險，任何持有這個 list 的地方都會看到更新後的內容。
- **長期記憶**：不用另外處理，`run_agent()` 每次都會透過 `build_system_prompt()` 讀取檔案。
- **為什麼短期記憶可以放心截斷？** 因為真正重要的事（名字、偏好），模型已經用 `remember` 存進長期記憶了。這就是 10.2 節「上課的印象」和「筆記本」的分工。

**預期輸出（真的模型；你輸入的內容不同，回答就會不同）：**

### 程式 10-7：關鍵字搜尋的極限

這段**不需要 API key**。

```python
test_questions = [
    "退選的期限是什麼時候？",     # 用詞和資料一樣
    "放棄一門課要怎麼辦？",       # 意思同「退選」，但用詞不同
    "書可以借多久？",             # 意思同「借期」，但用詞不同
    "生病不能上課怎麼辦？",       # 應該找「請假規定」
]

for q in test_questions:
    result = search_notes(q)
    titles = [r["title"] for r in result["results"]]
    print(f"{q}")
    print(f"    兩字組：{sorted(make_bigrams(q))}")
    print(f"    結果：{titles if titles else '找不到'}")
```

**逐段解說：**

- 四個問題：第一個用詞和資料完全一樣；後三個是「意思對、用詞不同」的問法。
- 印出每個問題切出來的兩字組，以及搜尋結果，看看問題出在哪裡。

**預期輸出：**

```text
退選的期限是什麼時候？
    兩字組：['時候', '期限', '退選']
    結果：['加退選規定']
放棄一門課要怎麼辦？
    兩字組：['一門', '放棄', '棄一', '門課']
    結果：找不到
書可以借多久？
    兩字組：['以借', '借多', '多久']
    結果：找不到
生病不能上課怎麼辦？
    兩字組：['上課', '不能', '生病', '病不', '能上']
    結果：['加退選規定']
```

**觀察重點：**

- **「放棄一門課」**：資料裡寫的是「退選」「停修」，沒有任何一組字對得上，所以找不到。
- **「書可以借多久」**：資料寫「借期 30 天」，但切出來的「借多」「多久」都不在資料裡。
- **「生病不能上課」**：更糟，**找錯了**！它應該找「請假規定」，卻因為「不能」兩個字剛好出現在加退選規定裡（「第三週起不能再加選」），被當成相關資料。如果模型照著這份錯的資料回答，就會答非所問。
- 這三個例子正是 10.7 節說的：關鍵字搜尋只看「字一不一樣」，不懂「意思一不一樣」。改用**向量搜尋（embedding）**就能改善，而 RAG 的整體架構（檢索 → 放進 prompt → 生成）完全不用改。

> 當 Agent 用 `search_notes` 找不到資料時，有些模型會**自己換個關鍵字再搜一次**（例如把「放棄一門課」改成「退選」），這是把搜尋做成工具的另一個好處。但不能依賴這一點，搜尋本身的品質還是最重要的。

## 【常見錯誤】

| 錯誤情況 | 原因 | 解決方式 |
|---------|------|---------|
| 傳了 `history=[]`，對話卻沒被記住 | 用 `if history:` 判斷，空 list 被當成「假」 | 判斷「有沒有傳」要用 `if history is not None` |
| `history` 越來越長，越聊越貴 | 沒有截斷 | 用 `trim_history()` 只保留最近幾則（第 3 章） |
| 把工具請求和結果也存進 `history` | 存太多細節 | 短期記憶只存問題和最終回答 |
| 關掉 Colab 再打開，長期記憶不見了 | Colab 的本機檔案會被清除 | 把 `MEMORY_FILE` 改存到 Google 雲端硬碟 |
| `json.decoder.JSONDecodeError` 讀記憶檔失敗 | 檔案內容被手動改壞了 | 刪掉或修正 `campus_memory.json`，或在 `load_memory()` 多接這個例外 |
| 長期記憶被寫進奇怪的指令 | 提示注入騙模型呼叫 `remember` | 工具說明寫明「只記使用者說的話」；讓使用者能查看、刪除記憶 |
| 搜尋結果一直是空的 | 問題的用詞和資料不同；或停用詞設太多 | 調整資料寫法、停用詞，或改用向量搜尋 |
| 模型沒搜尋就直接回答學校規定 | 工具說明沒寫清楚「什麼時候一定要用」 | `description` 寫明「回答學校規定前一定要先搜尋」 |
| 模型搜尋到了，回答卻加油添醋 | 沒有要求「只根據搜尋結果回答」 | 在工具說明或 prompt 中明確要求，搜尋不到就說不確定 |

## 【本章小結】

1. 記憶和知識的本質都一樣：**在呼叫模型前，把相關的文字放進 messages**。差別只在文字從哪裡來。
2. **短期記憶**是這次對話的內容：`run_agent()` 的 `history` 參數只存問題和最終回答，再用 `trim_history()` 控制長度。
3. **長期記憶**存在檔案裡：模型用 `remember` 工具決定記什麼，`build_system_prompt()` 每次把記憶寫進 system prompt；要注意 Colab 檔案會消失，以及記憶也可能被提示注入污染。
4. **RAG（檢索增強生成）**＝先檢索相關資料、放進 prompt、再讓模型生成回答，就像開書考；把搜尋做成工具，模型就能自己決定什麼時候查、怎麼查。
5. 關鍵字搜尋只比對「字」，遇到同義詞會找不到、甚至找錯；真正的系統常用向量搜尋（embedding），但 RAG 的架構不變。
