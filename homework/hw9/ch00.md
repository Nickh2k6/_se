# 第 0 章　寫在開始之前

## 【本章重點】

這本書會帶你從零開始，**不靠任何框架**，親手寫出一個能自己查課表、看時間、算數學的「校園小助理 Agent」。
開始之前只要準備兩件事：一個 **Google Colab** 筆記本，以及一把存在 Colab **密鑰（Secrets）** 裡的 **Gemini API key**。
沒有 API key 也能讀：第 4 章起會提供「假的 LLM」，讓你不花錢、不連網也能跑通整個流程。

## 【觀念解說】

### 0.1 這本書要帶你做出什麼

先看終點。讀完全書，你會有一個在 Colab 裡執行的「校園小助理 Agent」。你問它一句話，它會**自己決定**要用哪些工具、用幾次，最後才回答你。

下面是它最後的樣子（第 7 章起你就會看到這種輸出）：

```text
你：明天第一堂課是幾點？如果 8 點出門，來得及嗎？

[第 1 步] 思考：我需要知道今天星期幾，才能推算「明天」。
          行動：get_current_time()
          觀察：2026-11-27 星期五 21:30

[第 2 步] 思考：明天是星期六，查星期六的課表。
          行動：get_schedule(day="星期六")
          觀察：{"day": "星期六", "courses": []}

[第 3 步] 最終回答：明天是星期六，你沒有課，不用出門喔！
```

注意看：**你只問了一句話**，它卻自己做了「查時間 → 查課表 → 回答」三個步驟。這就是 **Agent（代理人）** 和普通聊天機器人最大的不同。

> **Agent（代理人）**：能自己決定「下一步要做什麼」，並且使用工具把事情做完的 AI 程式。
> 第 7 章會正式定義它，現在先記住這個樣子就好。

這個小助理會有四個**工具（tool）**，也就是你寫好、讓 AI 可以「指定使用」的 Python 函式：

| 工具 | 做什麼 | 資料從哪來 |
|------|--------|-----------|
| `calculator` | 計算算式，例如學分加總 | Python 計算 |
| `get_current_time` | 取得現在的日期與時間 | 電腦時鐘 |
| `get_schedule` | 查詢某一天的課表 | 一份**假的**課表（Python dict） |
| `get_weather` | 查詢天氣 | 一份**假的**天氣資料（Python dict） |

課表和天氣都是假資料，因為這本書的重點是「Agent 怎麼運作」，不是「怎麼串接學校系統」。等你懂了機制，把假資料換成真的 API 只是小事。

### 0.4 準備 Google Colab

**Google Colab**（全名 Colaboratory）是 Google 提供的**免費線上 Python 環境**。你不用在自己電腦上安裝任何東西，打開瀏覽器就能寫 Python、跑 Python。

用一個比喻：Colab 像是**學校電腦教室裡的一台電腦**。你走進去就能用，常用的軟體都裝好了；但你離開太久，管理員會把電腦重開，你在上面裝的東西就不見了（筆記本檔案本身會留在你的 Google 雲端硬碟）。

**開始使用的步驟：**

1. 用瀏覽器打開 <https://colab.research.google.com>，用 Google 帳號登入。
2. 點「**新增筆記本**」（New notebook）。
3. 左上角的檔名 `Untitled0.ipynb` 可以點兩下改名，例如改成 `校園小助理.ipynb`。

**幾個基本名詞：**

- **筆記本（notebook）**：一份 `.ipynb` 檔案，裡面由很多個「儲存格」組成。
- **儲存格（cell）**：一小格可以單獨執行的程式。點儲存格左邊的 ▶ 按鈕，或按 `Shift + Enter` 就會執行。
- **執行階段（runtime）**：Colab 背後真正在跑你程式的那台雲端電腦。閒置太久（大約數十分鐘到一個多小時）會被**中斷連線**，之前跑過的變數會全部消失，要從頭重新執行儲存格。

> **重要觀念**：儲存格之間的變數是**共用**的。你在第 1 格寫 `x = 5`，第 2 格就可以 `print(x)`。
> 這也代表：如果執行階段重新啟動，你要**從上往下重跑一次**，後面的格子才找得到前面定義的東西。

**`!pip install` 是什麼？**

Python 有很多別人寫好的工具包，叫做**套件（package）**。`pip` 是 Python 用來安裝套件的指令。在 Colab 的儲存格裡，開頭加上驚嘆號 `!` 代表「這行不是 Python，而是交給系統的指令」。

```text
!pip install google-genai      ← 安裝 Google 官方的 Gemini 套件（第 2 章才會用到）
```

本書每一章如果需要安裝套件，都會在那章的【動手做】最前面列出來。因為執行階段重啟後安裝的套件會不見，**每次重新打開筆記本都要重跑一次 `!pip install`**。

### 0.5 申請 Gemini API key

**API（Application Programming Interface，應用程式介面）**：一個程式「對外開放的窗口」，讓別的程式可以照規定的格式跟它溝通。第 2 章會詳細說明。

**API key（API 金鑰）**：一串很長的文字密碼，用來證明「這個請求是誰送的」。Google 靠它來知道是誰在用、用了多少、該不該擋下來。

比喻：API key 就像你的**學生證**。進圖書館要刷學生證，圖書館才知道是你、借了幾本書。如果學生證被別人撿走，別人就能用你的名義借書 —— 而且**帳算在你頭上**。

**申請步驟：**

1. 打開 **Google AI Studio**：<https://aistudio.google.com>，用 Google 帳號登入。
2. 找到「**Get API key**」（取得 API 金鑰）的頁面。
3. 點「**Create API key**」（建立 API 金鑰）。如果它要你選一個 Google Cloud 專案，照畫面指示建立或選擇一個即可。
4. 畫面會出現一串很長的文字，**按複製**。

> 介面的按鈕名稱和位置 Google 會不定期調整。如果找不到，請以 AI Studio 當下的畫面或官方文件為準。

**關於免費額度：**

Gemini API 目前提供**免費額度（free tier）**，學生做練習通常夠用，不需要綁信用卡。但免費額度有限制，例如：

- **每分鐘請求數**有上限 —— 跑太快會收到 `429` 錯誤（意思是「太多請求了，請稍等」），等一下再跑就好。
- **每天的請求數**也有上限。
- 免費方案送出的內容，Google 可能會用來改善產品，所以**不要送出個人隱私或機密資料**。

各模型的實際數字會變動，請以官方的「Rate limits」（速率限制）頁面為準。

### 0.6 把 API key 放進 Colab 密鑰

**這一節是整本書最重要的安全規則：API key 絕對不可以直接寫在程式碼裡。**

錯誤示範（**千萬不要這樣做**）：

```python
# ❌ 錯誤示範：把金鑰直接寫在程式裡
api_key = "AIzaSy......這裡是一長串金鑰"
```

為什麼不行？因為筆記本很容易被分享出去：

- 你把 `.ipynb` 傳給同學、上傳到 GitHub、交作業給老師 —— 金鑰就跟著一起送出去了。
- 有些人會專門在 GitHub 上掃描外洩的金鑰，拿去盜用。
- 被盜用的額度和費用，都算在你的帳號上。

**正確做法：用 Colab 的密鑰（Secrets）功能。**

密鑰功能是 Colab 幫你保管的「**私人保險箱**」。金鑰存在保險箱裡，程式要用時再去拿。分享筆記本時，**保險箱不會跟著被分享**。

```text
  你的 Colab 筆記本
  │
  ├─ 程式碼（會跟著筆記本被分享）
  │     api_key = userdata.get("GEMINI_API_KEY")
  │                     │
  │                     │ 執行時才去保險箱拿
  │                     ▼
  └─ 🔑 密鑰 Secrets（只有你看得到，不會被分享）
        GEMINI_API_KEY = AIzaSy......
```

**設定步驟：**

1. 在 Colab 左邊的側邊欄，點**鑰匙圖示 🔑**（密鑰 / Secrets）。
2. 點「**新增密鑰**」（Add new secret）。
3. **名稱（Name）** 填：`GEMINI_API_KEY`（全書都用這個名稱，請一字不差）。
4. **值（Value）** 貼上剛剛複製的 API key。
5. 打開這一列的「**筆記本存取權**」（Notebook access）開關。沒打開的話，程式讀不到。

設定好之後，就可以用下一段【動手做】的程式確認有沒有讀到。

### 0.7 沒有 API key 也沒關係：mock LLM

有些讀者可能暫時拿不到 API key（例如帳號限制、網路問題），或是額度用完了。為了讓大家都能讀下去，本書從第 4 章起會提供一個**假的 LLM 函式**，叫做 `mock_llm()`。

**Mock（模擬物）**：在軟體開發裡，指「一個假裝成真東西的替身」。它的輸入、輸出格式和真的一模一樣，但裡面只是照著寫好的規則回答。

比喻：mock LLM 像是**駕訓班的模擬駕駛艙**。方向盤、油門、儀表板跟真車一樣，你可以完整練習「看到紅燈 → 踩煞車」的流程，但不會真的開上馬路，也不用加油。

```text
  真的 LLM：   你的程式 ──▶ call_llm(messages) ──▶ 網路 ──▶ Google 伺服器 ──▶ 回答
  假的 LLM：   你的程式 ──▶ mock_llm(messages) ──▶ 照規則挑一個寫好的回答
                         ▲
                    呼叫方式一模一樣，所以可以直接替換
```

mock LLM 當然不聰明，它只會回答幾種寫好的情境。但本書後半段的重點是「**Agent 的流程怎麼運作**」（誰呼叫誰、資料怎麼傳），而不是模型有多聰明。對理解機制來說，mock LLM 就夠用了。

### 0.8 模型會更新：遇到錯誤時怎麼辦

LLM 這個領域變化非常快，可能每幾個月就有新模型，舊模型會被**停用（deprecated，被標記為即將淘汰）**，SDK 的寫法也可能調整。本書寫作時採用：

- Google 官方的 Python SDK：**`google-genai`**（程式裡寫成 `from google import genai`）
- 模型名稱統一放在一個變數 `MODEL_NAME` 裡（第 2 章會設定），要換模型只改一個地方

> ⚠️ **注意**：網路上很多舊教學用的是另一個套件 `google-generativeai`（程式裡寫成 `import google.generativeai as genai`）。那是**舊版 SDK**，寫法不一樣。本書一律用新版的 `google-genai`，不要混用。

**如果照書上的程式執行卻出錯**，請照這個順序檢查：

1. 先看錯誤訊息的**最後一行**，翻**附錄 B**找有沒有一樣的錯誤。
2. 打開 Gemini API 官方文件：<https://ai.google.dev/gemini-api/docs>，確認：
   - **模型名稱**是否還存在（看「Models」頁面）
   - **SDK 寫法**是否有改（看「Quickstart」或對應功能的頁面）
3. 把 `MODEL_NAME` 換成官方文件上目前列出的模型名稱，再跑一次。

### 程式 0-2：確認讀得到 API key

請先完成 0.6 節的設定，再執行這段。

```python
from google.colab import userdata

# 從 Colab 密鑰（保險箱）讀取 API key
api_key = userdata.get("GEMINI_API_KEY")

# 只顯示前 4 個字和長度，確認有讀到就好；不要把整串印出來
```

## 【常見錯誤】

| 錯誤情況 | 原因 | 解決方式 |
|---------|------|---------|
| `SecretNotFoundError` | 密鑰名稱打錯，或根本沒建立 | 檢查左側 🔑 面板，名稱必須是 `GEMINI_API_KEY`，大小寫一樣、前後沒有空白 |
| `NotebookAccessError` | 沒打開「筆記本存取權」開關 | 在 🔑 面板把那一列的開關打開，再重跑 |

## 【本章小結】

1. 全書目標：不用框架，親手做出會使用工具、能自己決定步驟的「校園小助理 Agent」。
2. 全書像蓋五層樓：API → 對話記憶 → 結構化輸出 → 工具呼叫 → Agent 迴圈，每一層都是因為下面那層不夠用才出現。
3. Colab 是免費的線上 Python 環境；執行階段重啟後，變數和安裝的套件都會消失，要從上往下重跑。
4. API key 一定要放在 Colab 密鑰（Secrets）裡，用 `userdata.get("GEMINI_API_KEY")` 讀取，**絕對不要寫死在程式碼中**。
5. 沒有 API key 的讀者，第 4 章起可以用 mock LLM 跑通流程；程式出錯時，先查附錄 B，再對照官方文件。
